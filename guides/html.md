# Гайд по HTML-верстке

Этот документ описывает подход к HTML-разметке. Правила именования классов и правила стилизации описываются отдельно. Здесь важны структура, компонентность, семантика, переиспользуемость и логика разбиения интерфейса на блоки.

## Цель HTML-разметки

HTML должен описывать смысл и структуру интерфейса, а не внешний вид.

Хорошая разметка:

- читается без CSS;
- отражает иерархию контента;
- делится на переиспользуемые компоненты;
- не привязана к одному конкретному экрану без необходимости;
- позволяет менять стили без переписывания структуры;
- остаётся понятной другому разработчику через несколько месяцев.

## Базовые принципы

### Регистр текста

Если текст в макете набран заглавными буквами, в HTML-разметке он переводится в обычный регистр: заглавной остается только первая буква в начале предложения. Визуальный капс, если он нужен по макету, задается через CSS, а не через текст в HTML.

Исключение — аббревиатуры, краткие технические обозначения и устоявшиеся сокращенные названия. Если такое название принято писать заглавными буквами, в HTML оно сохраняется заглавными буквами: например, `ТПЛ`, `ПВХ`, `ГОСТ`.

### 1. Сначала структура, потом внешний вид

Перед версткой нужно определить:

- какие на странице есть крупные секции;
- какие внутри секций есть повторяемые блоки;
- какие элементы являются самостоятельными компонентами;
- какие компоненты являются частью комплексного компонента;
- какие блоки можно переиспользовать на других страницах.

Не стоит начинать с декоративных оберток. Сначала размечается смысловая структура, затем добавляются технические контейнеры, если они действительно нужны.

Обертки используются только при явной необходимости. Перед добавлением обертки нужно понимать, какую задачу она решает.

На этапе HTML-разметки элемент получает только те классы, которые уже имеют понятную роль: компонент, элемент компонента, обязательный модификатор, общий layout-класс или JS-hook. Не добавляйте дополнительные классы "на будущее" и не дублируйте роль существующего класса без явной необходимости.

Если в процессе стилизации станет понятно, что существующих классов недостаточно для конкретной задачи, дополнительный класс можно добавить тогда. Такой класс должен решать реальную задачу, а не заранее страховать возможные будущие стили.

Плохо:

```html
<div class="grid-layout benefits-section__grid cards-grid">
	...
</div>
```

Хорошо:

```html
<div class="grid-layout">
	...
</div>
```

Верстка проекта строится по принципу mobile-first: HTML-структура должна оставаться простой и устойчивой на мобильном экране, а усложнение раскладок для больших экранов выполняется на уровне CSS.

### 2. HTML не должен дублировать CSS-логику

Нельзя создавать отдельный HTML-блок только потому, что "так удобнее покрасить". Обертка допустима, только если без нее нельзя корректно решить задачу:

- группирует связанный контент;
- нужна для компонента;
- нужна для layout-структуры;
- нужна для доступности;
- нужна для контейнера изображения или другого медиа;
- нужна для интеграции с JS.

Если обертка не несет смысловой, структурной или технической роли, ее не нужно использовать.

Плохо:

```html
<div class="footer__inner">
	<div class="footer__brand">
		<a class="logo" href="/">...</a>
	</div>
</div>
```

Хорошо:

```html
<footer class="footer">
	<div class="container">
		<a class="logo" href="/">...</a>
	</div>
</footer>
```

Обертки вроде `inner`, `content`, `body`, `top`, `bottom`, `brand` допустимы только тогда, когда они действительно группируют элементы или нужны для конкретной layout-задачи. Не добавляйте их по привычке.

### 3. Компонент должен быть переносимым

Компонент считается хорошим, если его можно перенести в другое место страницы или на другую страницу без изменения внутренней HTML-структуры.

Компонент не должен зависеть от случайного родителя. Контекст может менять расположение компонента, но не должен ломать его внутреннюю структуру.

## Компонентный подход

### Что считать компонентом

Компонент — это самостоятельный фрагмент интерфейса с понятной ролью.

Примеры компонентов:

- шапка сайта;
- логотип;
- навигация;
- кнопка;
- карточка товара;
- карточка преимущества;
- секционный заголовок;
- форма заявки;
- поле формы;
- футер;
- список контактов;
- блок с изображением и текстом.

Компонент может быть крупным или маленьким. Главное, чтобы у него была самостоятельная ответственность.

Логотип чаще всего считается отдельным компонентом, а не элементом шапки или футера. Один и тот же блок `logo` может использоваться в разных местах сайта, а контекст задается модификатором.

```html
<a class="logo logo--header" href="/" aria-label="Название компании">
	<img class="logo__image" src="" alt="Название компании" width="120" height="48" />
</a>
```

Не стоит называть логотип как элемент конкретной секции, если это один и тот же самостоятельный брендовый элемент.

### Структура компонента

У компонента должна быть предсказуемая структура:

```html
<article class="component">
	<div class="component__image-wrapper">
		<img class="component__image" src="" alt="" width="320" height="240" />
	</div>
	<div class="component__content">
		<span class="component__content-title">Заголовок</span>
		<p class="component__content-description">Описание</p>
	</div>
</article>
```

Внутри компонента элементы называются и группируются по роли:

- image-wrapper — обертка изображения, если она действительно нужна;
- image — изображение;
- body или content — содержательная часть;
- title — заголовок;
- description — описание;
- actions — действия;
- meta — вспомогательная информация.

Точные правила именования классов описаны в отдельном файле гайда по именованию классов, но сама логика ролей должна сохраняться.

Если обертка нужна только для одного изображения, используйте элемент `block__image-wrapper`. Класс `block__media` не используется для простой обертки вокруг `img`.

```html
<div class="product-card__image-wrapper">
	<img class="product-card__image" src="" alt="" width="540" height="360" />
</div>
```

Если обертка не нужна для структуры, доступности или будущей стилизации изображения, не добавляйте ее.

Класс `block__media` допустим только для сложной медиа-зоны, где внутри находится не одно изображение, а, например, видео, несколько изображений, подпись, контролы или смешанный медиа-контент.

### Компонент не должен знать слишком много

Компонент не должен содержать классы или структуру, которые описывают конкретную страницу, если это не его ответственность.

Плохо:

```html
<article class="home-page-third-section-orange-product-card">...</article>
```

Лучше:

```html
<article class="product-card">...</article>
```

Контекст страницы может обернуть компонент или добавить модификатор(лучший вариант), но базовый компонент должен оставаться самостоятельным.

## Абстрактные переиспользуемые блоки

Абстрактный блок — это структурный HTML-паттерн, который повторяется в разных местах, но не является конкретным контентным компонентом.

Примеры:

- общий контейнер;
- секция;
- секционный заголовок;
- группа кнопок;
- медиа-блок;
- карточка;
- список карточек;
- тело карточки;
- описание карточки;
- форма;
- поле формы.

Если несколько разных блоков имеют одинаковую HTML-роль, нужно выделить общий абстрактный класс.

Пример:

```html
<div class="section-header">
	<h2>Клейкая лента с логотипом</h2>
	<p>Описание секции</p>
</div>

<div class="section-header">
	<h2>Упаковочная лента</h2>
	<p>Описание секции</p>
</div>
```

Не нужно создавать разные классы для одинаковой структуры:

```html
<div class="catalog-lead">...</div>
<div class="packaging-head">...</div>
<div class="specialized-header">...</div>
```

Если эти блоки выполняют одну и ту же роль, должен быть один общий блок.

То же правило применяется к повторяемым колонкам, группам и другим layout-частям внутри одного компонента. Если несколько элементов выполняют одинаковую роль и имеют одинаковый структурный паттерн, они получают один общий класс, а не разные имена по содержанию.

Плохо:

```html
<div class="footer__nav">...</div>
<div class="footer__delivery">...</div>
<div class="footer__contacts">...</div>
```

Хорошо:

```html
<div class="footer__column">...</div>
<div class="footer__column">...</div>
<div class="footer__column">...</div>
```

## Когда создавать общий класс

Общий класс нужен, если:

- блоки имеют одинаковую роль;
- структура повторяется два и более раза;
- отличия касаются только контента;
- блоки должны выглядеть или вести себя одинаково;
- изменения одного блока потребуется применить к другим.

Общий класс не нужен, если:

- блоки похожи только визуально, но имеют разную смысловую роль;
- структура совпала случайно;
- один блок является уникальной промо-секцией;
- переиспользование усложнит чтение HTML.

## БЭМ как методология структуры

БЭМ помогает разделять интерфейс на независимые блоки, элементы и варианты состояния.

В этом документе не фиксируются конкретные правила именования. Важно понимать роли:

- блок — самостоятельный компонент;
- элемент — часть блока, которая не используется отдельно;
- модификатор — вариант блока или элемента.

### Блок

Блок должен быть самостоятельным.

```html
<article class="product-card">...</article>
```

Если фрагмент можно перенести в другое место и он сохранит смысл, это хороший кандидат на блок.

### Элемент

Элемент существует только внутри своего блока.

```html
<article class="product-card">
	<img class="product-card__image" src="" alt="" width="320" height="240" />
	<div class="product-card__body">
		<span class="product-card__title">Название</span>
	</div>
</article>
```

Элемент не должен использоваться отдельно от блока. Если элемент стал нужен сам по себе, возможно, он должен стать отдельным блоком.

### Модификатор

Модификатор описывает вариант блока или элемента.

```html
<article class="product-card product-card--featured">...</article>
```

Модификатор не должен заменять базовый класс. Он всегда дополняет базовый блок или элемент.

## Блоки и контекст

Компонент может находиться внутри контекстного блока страницы:

```html
<section class="catalog-section">
	<div class="container">
		<article class="product-card">...</article>
	</div>
</section>
```

Контекст отвечает за расположение компонента в секции. Сам компонент отвечает за свою внутреннюю структуру.

Не нужно смешивать эти ответственности.

## Семантическая структура страницы

Страница должна строиться из крупных смысловых областей:

```html
<body>
	<header>...</header>
	<main>
		<section>...</section>
		<section>...</section>
	</main>
	<footer>...</footer>
</body>
```

Рекомендации:

- на странице должен быть один основной `main`;
- крупные смысловые блоки оформляются через `section`;
- самостоятельные повторяемые карточки — через `article`;
- навигация — через `nav`;
- списки однотипных элементов — через `ul` / `ol`, если это действительно список;
- кнопки действий — через `button`;
- ссылки перехода — через `a`.

## Заголовки

Заголовки должны отражать иерархию контента.

По умолчанию в проекте используются только два уровня HTML-заголовков:

- `h1` — главный заголовок страницы;
- `h2` — заголовок крупной секции.

Оба уровня должны иметь соответствующие классы. Правила именования этих классов описываются в отдельном гайде по именованию классов.

Заголовок добавляется только тогда, когда он есть в макете или ТЗ как видимый текстовый объект. Название контейнера, фрейма, группы или слоя в дизайн-файле не считается заголовком и не переносится в HTML как текст.

Плохо:

```html
<div class="footer__nav">
	<span class="footer__nav-title">Разделы</span>
	<ul class="link-list">...</ul>
</div>
```

Хорошо:

```html
<div class="footer__nav">
	<ul class="link-list">...</ul>
</div>
```

Все остальные визуальные заголовки создаются через тег `span` с соответствующим классом. Это относится к заголовкам карточек, небольших блоков, пунктов преимуществ, элементов списков и другим локальным подзаголовкам.

Если внутри заголовка или строки нужно выделить цветом только один фрагмент текста, достаточно обернуть этот фрагмент в `span` без отдельного класса. Такой `span` стилизуется через контекст родительского класса.

```html
<h1 class="hero__title">Клейкая лента <span>для упаковки</span></h1>
```

Тег `<br>` по умолчанию не используется. Нельзя вставлять `<br>` ради визуального переноса строки в заголовке, кнопке, карточке или промо-блоке. Такие переносы должны управляться CSS и адаптивной шириной контейнера.

`<br>` допустим только в крайних случаях, когда перенос является частью содержания и должен сохраняться независимо от viewport: например, в адресе, стихотворной строке или юридически заданном тексте.

Плохо:

```html
<h2 class="section-title">Преимущества,<br />которые работают</h2>
```

Хорошо:

```html
<h2 class="section-title">Преимущества, которые работают</h2>
```

Короткие и смыслово связанные фрагменты не должны разрываться переносом строки. В видимом HTML-тексте для таких связок используется неразрывный пробел `&nbsp;`.

Неразрывный пробел ставится:

- после предлогов: `в&nbsp;каталог`, `для&nbsp;упаковки`, `на&nbsp;рынке`;
- после коротких союзов `и`, `или`: `и&nbsp;аксессуары`, `или&nbsp;товары`;
- внутри составных союзов и после них, если следующий фрагмент связан по смыслу: `а&nbsp;также&nbsp;аксессуары`;
- после частицы `не`: `не&nbsp;порвутся`, `не&nbsp;стирается`;
- между числом и следующим словом или единицей измерения: `14&nbsp;дней`, `10&nbsp;мб`, `2010&nbsp;года`;
- между частями сокращений и служебных обозначений, если они должны читаться вместе;
- вокруг тире в текстовых связках, где части фразы должны оставаться рядом: `НьюМарк&nbsp;—&nbsp;каталог`, `2&nbsp;дня&nbsp;—&nbsp;скидка`.

Плохо:

```html
<span class="product-card__conditions">Минимальная партия — 3 коробки · срок — 14 дней</span>
```

Хорошо:

```html
<span class="product-card__conditions">Минимальная партия&nbsp;—&nbsp;3&nbsp;коробки · срок&nbsp;—&nbsp;14&nbsp;дней</span>
```

Это правило относится только к видимым областям сайта: заголовкам, описаниям, кнопкам, ссылкам, пунктам меню, подписям полей и placeholder. Внутри тега `head` и в метатегах неразрывные пробелы не используются: `title`, `meta description`, `meta keywords`, Open Graph, Twitter Card и другие служебные данные пишутся с обычными пробелами. Обычные слова не связываются неразрывным пробелом без необходимости.

Если на странице используется общий блок `section-header`, секционный заголовок всегда помещается внутрь него. Это правило сохраняется и для секций без описания: отсутствие `section-description` не отменяет обертку `section-header`. Так секции остаются единообразными, а стили заголовочных зон не зависят от наличия дополнительного текста.

```html
<div class="section-header">
	<h2 class="section-title">Почему сотрудничать с нами выгодно</h2>
</div>
```

Пример:

```html
<main>
	<section>
		<h1 class="page-title">Главный заголовок страницы</h1>
	</section>

	<section>
		<div class="section-header">
			<h2 class="section-title">Раздел каталога</h2>
			<p class="section-description">Описание секции</p>
		</div>
		<article>
			<span class="card-title">Карточка категории</span>
		</article>
	</section>
</main>
```

Не стоит выбирать уровень заголовка из-за размера текста. Размер — задача CSS. Уровень — задача HTML. Если нужен визуальный заголовок ниже уровня секции, используйте `span` с классом.

## Декоративные элементы

Статические декоративные элементы не добавляются в HTML отдельными тегами. Линии, разделители, плашки, фоновые акценты и похожий декор реализуются через CSS: `border`, `background`, `box-shadow`, псевдоэлементы `::before` / `::after` и другие стилевые средства.

Исключение допустимо только тогда, когда декоративный элемент действительно нужен как часть поведения: например, является отдельной целью для анимации, используется библиотекой вроде GSAP, управляется JavaScript или не может быть корректно реализован средствами CSS без ухудшения структуры.

Плохо:

```html
<div class="hero__divider" aria-hidden="true"></div>
```

Хорошо:

```css
.hero__title::after {
	content: "";
	display: block;
	width: 92px;
	height: 2px;
	background-color: var(--color-accent);
}
```

## Изображения

Изображение должно иметь понятную роль.

Контентное изображение:

```html
<img src="product.jpg" alt="Рулон упаковочной ленты" width="120" height="120" />
```

Декоративное изображение:

```html
<img src="decor.svg" alt="" aria-hidden="true" width="120" height="120" />
```

У изображения всегда должны быть явно заданы `width` и `height`.

Если изображение передает смысл, `alt` обязателен. Если изображение декоративное, оно не должно мешать экранным читалкам.

## Кнопки и ссылки

Используйте `a`, если действие ведет пользователя по ссылке:

```html
<a href="/catalog" class="button">Перейти в каталог</a>
```

Используйте `button`, если действие происходит на текущей странице:

```html
<button type="submit" class="button">Отправить заявку</button>
```

Не нужно использовать `div` или любой другой тег, как кнопку.

Если несколько кнопок или ссылок-кнопок нужно объединить в одну layout-группу, обертка получает общий класс `button-row`.

```html
<div class="button-row hero__actions">
	<button class="button button--primary" type="button">Оставить заявку</button>
	<a class="button button--secondary" href="/catalog">Перейти в каталог</a>
</div>
```

## Формы

Форма должна быть доступной и понятной без CSS.

```html
<form class="request-form">
	<label class="field">
		<span class="field__label">Имя</span>
		<input class="field__control" type="text" name="name" />
	</label>

	<button class="button" type="submit">Отправить заявку</button>
</form>
```

Каждое поле должно иметь подпись. Placeholder не заменяет label.

## Контейнеры и layout-обертки

Контейнер нужен для ограничения ширины и выравнивания контента.

Любая layout-обертка должна иметь явную причину: ограничение ширины, группировка связанных элементов, независимая сетка, позиционирование, доступность, JS-хук или необходимость стилизовать компонент так, как без этой обертки нельзя.

```html
<section class="section">
	<div class="container">...</div>
</section>
```

Контейнер должен быть всегда внутри блока или секции:

```html
<header class="header">
	<div class="container">...</div>
</header>
```

Для базовых блоков шапки и футера используем простые классы `header` и `footer`. Не утяжеляем их дополнительными префиксами, если в проекте нет нескольких разных сущностей шапок или футеров.

Не нужно ограничивать ширину самого full-width блока, если по макету фон или рамка должны идти на всю ширину.

## Повторяемые карточки

Если карточки повторяются, их структура должна быть одинаковой.

```html
<div class="grid-layout">
	<article class="feature-card">
		<span class="feature-card__title">Подбор под задачу</span>
		<p class="card-description">Описание</p>
	</article>

	<article class="feature-card">
		<span class="feature-card__title">Оптовые поставки</span>
		<p class="card-description">Описание</p>
	</article>
</div>
```

Для повторяемой сеточной раскладки используется общий класс `grid-layout`. Он описывает базовый layout-паттерн, а не конкретный контент внутри сетки.

Если общей сетки достаточно, второй класс не добавляется:

```html
<div class="grid-layout">...</div>
```

Если конкретной секции действительно нужна своя отличающаяся раскладка, можно добавить элемент этой секции или группы:

```html
<div class="grid-layout catalog-section__grid">...</div>
<div class="grid-layout catalog-group__grid">...</div>
<div class="grid-layout benefits-section__grid">...</div>
```

`grid-layout` отвечает за общую сеточную основу. `catalog-section__grid`, `catalog-group__grid` или `benefits-section__grid` добавляются только тогда, когда отвечают за конкретную композицию: количество колонок, `gap`, выравнивание, `grid-column` для отдельных элементов.

Не используйте контентные имена вроде `cards-grid`, если сетка является абстрактным layout-паттерном и может содержать разные компоненты.

Одинаковые части карточек должны получать общий абстрактный класс, если они действительно выполняют одну роль.

## Чего избегать

Избегайте:

- разных классов для одинаковых структурных блоков;
- HTML, который повторяет визуальные детали вместо смысла;
- большого количества одноразовых оберток;
- `div` вместо семантических тегов;
- заголовков, выбранных по размеру, а не по иерархии;
- inline-стилей;
- классов, привязанных к случайной позиции блока;
- компонентов, которые работают только в одном родителе;
- декоративных элементов, которые не нужны для структуры.

## Чеклист перед сдачей HTML

- Страница разделена на `header`, `main`, `section`, `footer`.
- Повторяемые блоки оформлены как компоненты.
- Одинаковые структурные паттерны вынесены в общие классы.
- У компонентов есть понятная внутренняя иерархия.
- Блоки не зависят от случайного родителя.
- На странице используются только `h1` и `h2`; остальные визуальные заголовки сделаны через `span`.
- Изображения имеют корректный `alt`, `width`, `height`.
- Кнопки и ссылки используют правильные теги.
- Формы имеют `label`.
- В HTML нет inline-стилей.
- Нет разных классов для одного и того же структурного блока.
