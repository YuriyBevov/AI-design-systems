# Гайд для ИИ-агентов

Этот документ описывает правила работы ИИ-агентов с техническим заданием, дизайн-макетом, контентом и кодом проекта.

Цель гайда — не допускать самовольных решений, которые меняют смысл макета, структуру интерфейса или текст без прямого указания.

## Источник истины

Главные источники истины:

- техническое задание;
- дизайн-макет;
- существующие проектные гайды;
- уже утвержденная структура проекта.

При верстке агент всегда руководствуется актуальными гайдами из папки `guides`. Эти документы обязательны к применению и имеют приоритет над привычками агента, типовыми шаблонами и субъективными улучшениями.

Если между источниками есть противоречие, агент не должен придумывать решение молча. Нужно явно отметить противоречие и выбрать самый безопасный вариант: сохранить данные из ТЗ или макета без расширения.

## Не добавлять лишние элементы

Агент не добавляет элементы, которых нет в техническом задании или дизайн-макете.

Это касается:

- текстовых блоков;
- заголовков;
- кнопок;
- иконок;
- декоративных элементов;
- изображений;
- ссылок;
- полей формы;
- оберток без явной необходимости;
- вспомогательных UI-элементов.

Если элемент кажется полезным для семантики, доступности или удобства, но его нет в ТЗ или макете, агент не добавляет его самостоятельно. Допустимы только технически необходимые атрибуты и невидимые для пользователя улучшения, которые не меняют интерфейс и содержание.

Плохо:

```html
<span class="footer-nav__title">Доставка</span>
```

Если такого заголовка нет в макете или ТЗ, его не должно быть в разметке.

## Не менять текст

Агент никогда не переписывает, не расширяет и не сокращает текст из технического задания или дизайн-макета по своему усмотрению.

Запрещено:

- менять формулировки;
- добавлять новые предложения;
- удалять части текста;
- заменять тональность;
- улучшать маркетинговый смысл;
- уточнять текст без запроса;
- добавлять пояснения, которых не было в источнике.

Допустима только аккуратная орфографическая правка, если она не меняет смысл, стиль, объем и структуру текста.

Плохо:

```text
Исходный текст: Оставьте заявку
Текст агента: Оставьте заявку, и наш менеджер свяжется с вами в течение 15 минут
```

Хорошо:

```text
Исходный текст: Быстрое сроки производства
Правка: Быстрые сроки производства
```

Если есть сомнение, является ли изменение текста орфографической правкой или уже редактурой, агент должен сохранить исходный текст и предложить замену в файле agent-suggestions.md.

## Предложения по улучшению

Если в процессе работы у агента появляются предложения по улучшению, он не внедряет их самостоятельно и не смешивает с основной задачей.

Такие предложения фиксируются в отдельном файле внутри папки текущего проекта.

Название файла:

```text
agent-suggestions.md
```

В этот файл можно выносить:

- замечания по структуре;
- идеи по улучшению доступности;
- предложения по упрощению разметки;
- возможные улучшения дизайна;
- рекомендации по текстам;
- технические долги;
- вопросы, которые требуют решения владельца проекта.

Файл с предложениями не заменяет техническое задание и не дает агенту права менять макет или текст без отдельного запроса.

## Правило по умолчанию

По умолчанию агент переносит макет и ТЗ максимально буквально.

Любое улучшение, которого нет в источнике, считается изменением требований и не выполняется без отдельного запроса.
