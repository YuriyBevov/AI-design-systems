# РБУ «Хаджох»: выгрузка на сервер

## Формат сборки

Проект использует Astro в режиме Node standalone. Архив `release/rbuh-server.tar.gz` содержит готовые `dist/client` и `dist/server`, список зависимостей с lock-файлом, `.env.example`, `.nvmrc` и эту инструкцию. Исходники, локальный `node_modules` и пароли в архив не включаются.

Нужен хостинг с поддержкой Node.js, а не только статических HTML/PHP-файлов. Страницы и `/api/send-request` обслуживаются одним Node-процессом. Нельзя публиковать только `dist/client`: главная, каталог, прайс и отправка заявок требуют серверной части. Режим работы описан в [документации Astro Node](https://docs.astro.build/en/guides/integrations-guide/node/#standalone).

Используйте актуальную Node.js 24 LTS (ветка закреплена в `.nvmrc`), npm от 9.6.5. Минимум зависимостей проекта — Node.js 22.12.0. [Поддерживаемые версии Node.js](https://nodejs.org/en/about/previous-releases).

## Запуск готового архива

Загрузите `rbuh-server.tar.gz` и `rbuh-server.tar.gz.sha256` на сервер в отдельную папку релиза. Не распаковывайте новый релиз поверх работающего сайта. Сначала сохраните предыдущую сборку и серверный `.env` для отката.

В папке с архивом:

```sh
sha256sum -c rbuh-server.tar.gz.sha256
tar -xzf rbuh-server.tar.gz
npm ci --omit=dev
cp -n .env.example .env
chmod 600 .env
```

Заполните `.env` перед запуском. При обновлении перенесите существующие серверные настройки в новую папку. Не копируйте `node_modules` с компьютера разработчика: зависимости, включая Sharp, должны устанавливаться на целевой ОС.

```sh
npm start
```

По умолчанию приложение доступно на `http://127.0.0.1:4321`. Команда `npm start` загружает `.env`, если он существует; переменные, заданные хостингом, имеют приоритет. Для панели хостинга задайте рабочую папку распакованного релиза и команду запуска `npm start`. Если панель требует прослушивать все интерфейсы, задайте `HOST=0.0.0.0`; порт берётся из `PORT`.

Для постоянной работы настройте перезапуск процесса средствами хостинга или systemd. Домен и HTTPS направьте через обратный прокси на Node-приложение, включая `/api/send-request`, статические страницы и `/_astro/`. Не раздавайте корневую папку релиза как публичный каталог: `.env`, зависимости и `dist/server` не должны быть доступны по HTTP.

## Отправка заявок

Укажите в `.env`:

- `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE` — настройки почтового сервера;
- `SMTP_USER`, `SMTP_PASS` — SMTP-логин и пароль;
- `SMTP_FROM` — разрешённый отправитель (если пусто, используется логин);
- `SMTP_TO` — адрес получения заявок.

Для порта 465 обычно используется `SMTP_SECURE=true`, для STARTTLS на 587 — `false`; сверяйте значения с почтовым провайдером. После изменения `.env` перезапустите процесс. Без SMTP-конфигурации сайт открывается, но форма возвращает ошибку, а письмо не отправляется. Пароли не храните в Git и не присылайте в публичную переписку.

## Повторная сборка из репозитория

Рабочая папка в репозитории: `pen.dev/rbuh`.

```sh
cd pen.dev/rbuh
npm ci
npm run release
```

Команда оптимизирует изображения, собирает сайт и обновляет архив с SHA-256 в `release/`. Для локального просмотра исходников: `npm run dev`. Готовый архив уже собран: на сервере повторно запускать `build` не нужно, достаточно установить зависимости и выполнить `npm start`.

## Проверка после установки

Проверьте главную, `/services/`, `/price/`, все услуги и статичные страницы; загрузку стилей, шрифтов, изображений и SVG-спрайта. После настройки SMTP отправьте собственную тестовую заявку и убедитесь, что письмо получено. Реальная доставка писем без SMTP-доступов при подготовке архива не проверяется.

Полный прайс, реквизиты, часть условий и ссылки MAX/WhatsApp пока остаются в согласованном ранее состоянии. Подготовка сборки не заменяет их подтверждение перед публичным запуском.
