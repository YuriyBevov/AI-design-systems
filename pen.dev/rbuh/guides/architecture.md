# Архитектура проекта РБУ «Хаджох»

## 1. Источник и границы переноса

Проект `pen.dev/newmark/` используется как каркас. Копируются компонентные паттерны, базовые стили, клиентские сценарии и сборка. Контент, каталог, бренд и изображения Newmark не копируются в публичную часть.

Перед переносом составить перечень исходных файлов. Если компонент сильно связан с каталогом упаковки, создать адаптированную копию с нейтральным именем, а не оставлять старые сущности.

## 2. Слои проекта

- `src/pages/` — только маршруты и получение данных.
- `src/layouts/` — общий каркас страницы.
- `src/components/` — переиспользуемые UI-компоненты.
- `src/content/pages/` — статичные Markdown-страницы.
- `src/content/services/` — услуги и их детальные данные.
- `src/content/prices/` — группы цен и строки прайса.
- `src/content/site/` — контакты, компания, карта, отзывы и юридические ссылки.
- `src/images/` — управляемые ассеты приложения.
- `img/` — исходные фотографии заказчика; не редактировать и не удалять.
- `src/styles/main.scss` — единственная точка входа стилей.

`src/data/` и `src/templates/` не создавать: это дублирует `content`, `layouts` и `components`.

## 3. Layout

`BaseLayout` отвечает за:

- `html`, `head`, метаданные и язык;
- Header и Footer;
- основную область;
- сквозную заявку, если она включена для страницы;
- модальное окно;
- подключение основного клиентского JS и SCSS.

Страница не должна самостоятельно повторять эти зоны. Для юридических страниц layout принимает флаг отключения сквозной заявки.

`StaticPageLayout` отвечает за хлебные крошки и безопасный вывод Markdown-контента.

## 4. Контентная модель

Услуги и цены — разные сущности, связанные через стабильный `serviceId`.

- URL услуги строится из `slug`.
- Детальная страница получает объект услуги целиком.
- Прайс-фрагмент услуги выбирает группы с совпадающим `serviceId`.
- Полный прайс использует тот же массив групп без копирования строк.
- FAQ хранится централизованно и связывается по `faqIds`.

При удалении услуги сначала проверить связанные цены, FAQ, ссылки и навигацию. Не удалять объект молча, если есть зависимости.

## 5. Компоненты

Имена описывают сущность, а не место использования:

- `ServicesGrid`, не `HomeServices`;
- `FaqList`, не `ServiceFaq`;
- `PriceTable`, не `PricePageTable`;
- `YandexMap`, не `HomeMap`.

Один компонент должен поддерживать небольшие различия через props. Плитка услуг на главной и странице услуг не дублируется.

## 6. Стили и токены

- Цвета, шрифты, размеры контейнера, интервалы, переходы и z-index задаются токенами.
- Компонентные стили хранятся в `src/styles/components/`.
- Стили страниц допустимы только для уникальной композиции страницы.
- Не использовать `!important` без зафиксированной причины.
- Не привязывать компонент к тегу или конкретному месту страницы.
- Проверять `prefers-reduced-motion` для GSAP и иных анимаций.

## 7. SVG-спрайт и логотип

Иконки остаются в `src/sprite/` и собираются локальным плагином Newmark. Цвет видимых `fill`/`stroke` должен управляться через `currentColor`.

Логотип не включать в спрайт, если он имеет собственный `viewBox` и несколько цветовых версий. Хранить его отдельным SVG и импортировать как ассет или безопасно встраивать в компонент.

## 8. Изображения

- Исходники заказчика копируются в `src/images/source/`, но оригиналы в `img/` сохраняются.
- Оптимизированные версии создаются воспроизводимым скриптом.
- Визуалы выше первого экрана имеют eager-загрузку; остальные — lazy.
- Для локальных файлов использовать Astro `Image`.
- У каждого изображения есть роль, источник и `alt` в манифесте.
- Сгенерированные изображения отделены от реальных и не выдаются за документальную съёмку компании.

## 9. Клиентский JavaScript

`src/scripts/main.js` только импортирует и запускает функции `init...`.

Каждый интерактивный компонент:

- сам хранит дефолтные селекторы;
- корректно работает при отсутствии разметки;
- не инициализируется повторно;
- не ломает серверный HTML без JavaScript;
- снимает созданные обработчики, если это требуется режимом навигации.

## 10. Формы и сервер

- Endpoint и клиентская форма используют одинаковую схему полей.
- Поля валидируются до отправки и повторно на сервере.
- Вложения ограничены по типу и размеру.
- SMTP-настройки читаются только из окружения.
- В репозитории хранится только `.env.example` без секретов.
- Ответ API не раскрывает конфигурацию сервера и подробности внутренних ошибок.

## 11. Роуты и сборка

Динамические услуги собираются через `src/pages/services/[...slug].astro` с `getStaticPaths` и `prerender = true`, если серверная логика на странице не нужна. Формы могут работать через отдельный серверный endpoint при общем `output: "server"`.

Перед завершением изменения выполнить:

```bash
npm run build
```

Если добавлены проверки форматирования или тесты, выполнить и их. Сгенерированные артефакты сборки не коммитить без отдельного требования.
