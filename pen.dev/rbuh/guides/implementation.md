# Инструкция по реализации сайта

## 0. Входной контроль

Использовать подтверждённые данные из раздела 15 ТЗ: бренд РБУ «Хаджох», материал «мешанка», телефон `8-929-840-40-44`. Пока остальных данных нет, использовать явные `TODO`, нейтральный демонстрационный текст и состояние цены «По запросу» по правилам ТЗ.

## 1. Создать технический каркас

1. Перенести из Newmark конфигурацию Astro, PostCSS, browserslist, npm-скрипты и сборщик SVG-спрайта.
2. Переименовать пакет и дефолтные метаданные.
3. Подключить локальные Manrope для основного текста и Oswald для заголовков из `src/fonts`.
4. Перенести базовые layout-компоненты и скрипты поведения.
5. Удалить импорты контента и изображений Newmark.
6. Удалить скрипты импорта упаковочного каталога.
7. Выполнить пустую сборку до начала наполнения.

## 2. Создать дизайн-систему

1. Заменить токены Newmark на палитру из ТЗ.
2. Проверить контраст текста, ссылок, кнопок и focus-состояний.
3. Сохранить геометрию контейнера и модульную сетку как отправную точку.
4. Адаптировать карточки под услуги, сохранив общий ритм и индустриальный характер.
5. Создать SVG-логотип после подтверждения названия.
6. Подготовить favicon и Open Graph-изображение после утверждения знака.

## 3. Подготовить данные сайта

Создать:

- `src/content/site/company.js`;
- `src/content/site/contacts.js`;
- `src/content/site/socials.js`;
- `src/content/site/legal.js`;
- `src/content/site/map.js`;
- `src/content/site/reviews.js`;
- `src/content/services/services.js`;
- `src/content/services/faq.js`;
- `src/content/prices/groups.js`;
- индексные модули для каждого раздела.

Добавить валидатор данных или сборочные проверки:

- уникальность `id` и `slug` услуг;
- существование `serviceId` у каждой группы цен;
- существование всех `faqIds`;
- отсутствие пустых `title`, SEO-полей и обязательных `alt`;
- отсутствие ссылок и названий Newmark.

## 4. Подготовить изображения

1. Скопировать шесть исходников заказчика в `src/images/source/`, сохранив `img/`.
2. Дать понятные имена копиям.
3. Создать WebP/AVIF с корректной ориентацией и без метаданных, если это предусмотрено скриптом.
4. Закрепить `hero.jpeg` только за hero.
5. Составить манифест ролей и alt-текстов.
6. Определить недостающие роли.
7. Сгенерировать только недостающие изображения по `ai-images.md`.
8. Визуально проверить артефакты генерации, технику, руки, надписи и соответствие серии.

## 5. Собрать сквозные компоненты

1. `Header` и мобильное меню.
2. `Footer`.
3. `Modal` обратного звонка.
4. `RequestSection` и API отправки.
5. `Breadcrumbs`.
6. Базовые кнопки, списки ссылок, соцсети и таблицы.

После этого проверить навигацию без контентных страниц, клавиатуру и мобильное меню.

## 6. Реализовать главную

Собирать блоки в порядке из ТЗ. Каждый крупный повторяемый блок вынести в компонент. Не хранить объекты услуг и FAQ внутри `HomePage.astro`.

Особое внимание:

- hero использует `hero.jpeg`;
- реальный контент не смешивается с временными примерами;
- FAQ не содержит неподтверждённых условий;
- блок отзывов получает карточки из `src/content/site/reviews.js` и использует компактную классическую структуру;
- карта получает конфигурацию из контента.

## 7. Реализовать услуги

1. Создать `/services/` с четырьмя услугами; щебень, песок, мешанка и отсев объединить в одну услугу.
2. Реализовать единый `ServicesGrid`.
3. Создать динамический роут услуг.
4. Реализовать галерею/изображение, описание, параметры, цены, FAQ и карту.
5. Проверить хлебные крошки и уникальные метаданные.
6. Проверить страницы всех услуг, а не только первой.

## 8. Реализовать прайс-лист

1. Создать `PriceTable` из общих данных.
2. Вывести все группы на `/price/` с явным расстоянием или разделителем.
3. На детальных страницах фильтровать те же группы по `serviceId`.
4. Добавить дату актуальности.
5. Проверить мобильный формат таблиц и длинные примечания.

## 9. Реализовать статичные страницы

Создать Markdown-файлы и общий динамический роут. Контент без подтверждения не заполнять правдоподобными выдумками. Юридические страницы допускается держать как непубликуемые черновики до получения материалов, если владелец не разрешил явные временные страницы.

## 10. Подключить внешние сервисы

- Яндекс Карта: временная конфигурация разрешена ТЗ, перед релизом заменить.
- Отзывы: официальный iframe подключать только по реальному идентификатору; временные карточки хранить отдельно для последующей замены.
- SMTP: подключать только через окружение.
- Аналитика: не устанавливать без отдельного выбора и правового основания.

## 11. Проверка

1. Выполнить `npm run build`.
2. Запустить локальный сервер и проверить все маршруты.
3. Проверить 360, 768, 1024 и 1440 px.
4. Проверить клавиатуру, фокус, меню, FAQ, модальные окна и формы.
5. Проверить сеть: нет 404, лишних сторонних запросов и тяжёлых изображений.
6. Проверить один `h1`, метаданные, alt и хлебные крошки.
7. Найти остатки `Newmark`, `НЬЮМАРК`, `лента`, `catalog` в публичном коде.
8. Пройти `ai-checklist.md`.

## 12. Передача результата

В отчёте указать:

- созданные маршруты;
- источники и роли изображений;
- какие данные остались временными;
- какие интеграции ожидают ключи/идентификаторы;
- команды запуска и сборки;
- результаты проверок;
- известные ограничения.
