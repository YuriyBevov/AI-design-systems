# Предложения по улучшению

## Актуальный статус

1. **HTML-разметка собрана** — основной `index.html` содержит рабочую семантическую структуру страницы. Экспорт из `.pen` оставлен ниже как справочный блок данных макета.

2. **SCSS-архитектура создана** — стили разнесены по структуре из гайда:
   - `abstracts/` — токены;
   - `base/` — reset, global, typography;
   - `layout/` — container, section, header, footer, grid;
   - `components/` — button, logo, nav, cards, form, cta, social-list, section-header;
   - `pages/` — home.

3. **Декоративные элементы вынесены в CSS** — оранжевые линии и визуальные оверлеи сделаны через псевдоэлементы, без пустых декоративных тегов в HTML.

4. **Гайды обновлены** — добавлены правила по регистру текста, `button-row`, `section-header`, запрету лишних классов, ограничению `<br>` и неразрывным пробелам только в видимых областях сайта.

## Шрифты из макета

В `.pen`-макете встречаются следующие семейства:

- `Manrope` — основной текстовый шрифт: навигация, описания, карточки, формы, подписи, футер.
- `Oswald` — акцентный шрифт: крупные заголовки, CTA-заголовки, кнопки и часть контактных акцентов.
- `IBM Plex Sans` — встречается в экспорте один раз. Похоже на артефакт отдельного элемента, потому что общий стиль макета построен на `Manrope` и `Oswald`.

В текущей верстке используются токены:

```scss
--font-primary: "Manrope", system-ui, -apple-system, "Segoe UI", sans-serif;
--font-accent: "Oswald", "Arial Narrow", var(--font-primary);
```

Локальные файлы `Manrope` и `Oswald` добавлены в `src/fonts/` и подключены через `@font-face`, чтобы верстка не зависела от Google Fonts.

## Что ещё можно улучшить

1. **Изображения** — текущие изображения подключены из `src/design/images/`. Для продакшна стоит отдельно подготовить `webp/avif` и responsive-версии.

2. **Счётчик в CTA** — сейчас значения статические, как в макете. Для рабочей версии нужен JS-таймер с реальной датой окончания акции.

3. **Мобильная навигация** — макет в основном десктопный. Для полноценной mobile-first версии стоит добавить бургер-меню и состояния открытия/закрытия.

4. **Контент из футера** — текущие колонки футера приведены к повторяемому паттерну без дополнительных заголовков разделов. Если в финальном макете появятся видимые заголовки колонок, их нужно будет добавить как реальный контент, а не как технические подписи.
