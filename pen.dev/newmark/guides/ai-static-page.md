# Создание статичной страницы Newmark

Гайд описывает порядок добавления статичных страниц через Astro-шаблон `StaticPage.astro`.

## Где хранится контент

Данные статичных страниц лежат в:

```text
src/content/pages/
```

Каждая страница хранится отдельным JSON-файлом. Имя файла должно совпадать со slug страницы.

Пример:

```text
src/content/pages/delivery.json
```

## Как формируется URL

URL берется из поля `slug`.

Примеры:

- `delivery` → `/delivery/`;
- `about` → `/about/`;
- `payment` → `/payment/`.

Slug пишется латиницей, в нижнем регистре, слова разделяются дефисом.

## Обязательные поля

- `slug` - URL страницы;
- `title` - внутреннее название страницы;
- `seoTitle` - содержимое тега `title`;
- `seoDescription` - содержимое `meta description`;
- `breadcrumbs` - хлебные крошки;
- `h1` - единственный основной заголовок страницы;
- `lead` - вводный текст;
- `contentBlocks` - массив контентных блоков;
Сквозная форма заявки перед футером не задается в данных статичной страницы. Она подключается на уровне общего layout и выводится на всех страницах сайта.

## Структура шаблона

Статичная страница состоит из двух основных зон:

- отдельный блок хлебных крошек с разметкой `.breadcrumbs > .container > .breadcrumbs__list`;
- блок `.content`, внутри которого находится весь контент страницы, начиная с `h1`.

Внутри `.content` элементы идут в обычном потоке без лишних оберток: `h1`, `p`, `h2`, `ul`, `ol`, `blockquote`, `figure`, `table` и другие смысловые элементы.

Если нужен явный разделитель или увеличенный смысловой отступ между частями контента, используется блок `separator`, который рендерится как тег `hr`.

## Поддерживаемые блоки

- `text` - текстовый блок с заголовком и абзацами;
- `image` - изображение с подписью;
- `list` - обычный маркированный список;
- `steps` - стилизованный список этапов `.step-list`;
- `table` - таблица параметров `.data-table`;
- `faq` - список вопросов и ответов `.faq-list`;
- `contacts` - контактная информация `.contact-list`;
- `separator` - смысловой разделитель `hr`;
Форма заявки перед футером не является частью `.content`: она сквозная и должна оставаться единой для всех страниц сайта.

## Вопросы пользователю

Перед созданием страницы ИИ должен запросить:

- название страницы;
- slug;
- h1;
- SEO title;
- SEO description;
- вводный текст;
- какие контентные блоки нужны;
- тексты для каждого блока;
- нужны ли изображения;
- alt-тексты для изображений;
- есть ли формулировки, которые нельзя редактировать.

## Проверка

После создания страницы ИИ должен проверить:

- страница собирается через `npm run build`;
- на странице только один `h1`;
- нет пустых блоков;
- хлебные крошки соответствуют URL;
- все изображения имеют `alt`;
- видимый текст соблюдает правила типографики проекта.
- в шаблоне не используются классы с универсальным префиксом `content-`;
- обычные текстовые элементы внутри `.content` не оборачиваются в дополнительные блоки.
- форма заявки не дублируется внутри `.content`, потому что она выводится сквозным блоком перед футером.
