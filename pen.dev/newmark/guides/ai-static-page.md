# Создание статичной страницы Newmark

Гайд описывает порядок добавления статичных страниц через Markdown-файлы и Astro-шаблон `StaticPage.astro`.

## Основной принцип

Клиент может передать обычный текст без разметки. Задача ИИ:

1. определить семантику текста;
2. привести текст к корректному Markdown;
3. заполнить frontmatter страницы;
4. сохранить страницу в `src/content/pages/`;
5. проверить сборку проекта.

Подробные правила Markdown-формата описаны в `src/content/README.md`. Перед созданием или редактированием контента статичных страниц ИИ должен сверяться с этим файлом.

## Где хранится контент

Контент статичных страниц лежит в:

```text
src/content/pages/
```

Каждая страница хранится отдельным Markdown-файлом. Имя файла должно совпадать со slug страницы.

Пример:

```text
src/content/pages/about.md
```

## Как формируется URL

URL берется из поля `slug` во frontmatter. Если `slug` не указан, используется имя файла.

Примеры:

- `delivery` -> `/delivery/`;
- `about` -> `/about/`;
- `payment` -> `/payment/`.

Slug пишется латиницей, в нижнем регистре, слова разделяются дефисом.

## Обязательные элементы

- frontmatter с `slug`, `title`, `seoTitle`, `seoDescription` и `breadcrumbs`;
- один Markdown-заголовок `#`, который становится единственным `h1`;
- основной контент в Markdown-формате;
- осмысленные `alt` для изображений.

Сквозная форма заявки перед футером не задается в Markdown. Она подключается на уровне общего layout и выводится на всех страницах сайта.

## Структура шаблона

Статичная страница состоит из двух основных зон:

- отдельный блок хлебных крошек с разметкой `.breadcrumbs > .container > .breadcrumbs__list`;
- блок `.content`, внутри которого находится весь Markdown-контент страницы, начиная с `h1`.

Внутри `.content` элементы идут в обычном потоке без лишних оберток: `h1`, `p`, `h2`, `ul`, `ol`, `blockquote`, `figure`, `table`, `hr` и визуальные компоненты, которые можно определить в Markdown.

## Поддерживаемые сущности Markdown

- `#`, `##`, `###` - заголовки;
- обычный текст - абзацы;
- `-` - маркированные списки;
- `1.` - нумерованные списки;
- `[текст](href)` - ссылки;
- `![alt](src)` - изображения;
- таблицы Markdown;
- `>` - цитаты;
- `---` - разделитель `hr`;
- `{{ slider: id }}` - слайдер, описанный во frontmatter.

## Вопросы пользователю

Перед созданием страницы ИИ должен запросить:

- название страницы;
- slug;
- SEO title;
- SEO description;
- текст страницы или черновик;
- нужны ли изображения или слайдер;
- alt-тексты для изображений;
- есть ли формулировки, которые нельзя редактировать.

## Проверка

После создания страницы ИИ должен проверить:

- страница собирается через `npm run build`;
- на странице только один `h1`;
- хлебные крошки соответствуют URL;
- все изображения имеют `alt`;
- текст соблюдает правила типографики проекта;
- Markdown не содержит лишней HTML-разметки;
- форма заявки не дублируется внутри `.content`, потому что она выводится сквозным блоком перед футером.
