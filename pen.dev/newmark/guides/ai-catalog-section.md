# Раздел каталога

Инструкция описывает создание и обновление страницы раздела каталога, например `Клейкая лента с логотипом`.

## Структура страницы

Страница раздела каталога должна использовать универсальный шаблон `CatalogSectionPage`. Новые разделы добавляются через `src/content/catalog/categories.js`, а не копированием Astro-страниц.

Разделы каталога собираются динамическим роутом `src/pages/catalog/[...slug].astro`, поэтому вложенность задается полями `parentId` и `slug` в объекте категории. Финальный URL руками не хранится, он строится автоматически из цепочки родителей.

Товары для страницы раздела выбираются по самому разделу и всем его вложенным подразделам. Например, страница `catalog/kleikaya-lenta` показывает товары с `parentId: "kleikaya-lenta"` и товары всех дочерних подразделов. Страница `catalog/kleikaya-lenta/malyarnaya-lenta` показывает только товары `malyarnaya-lenta` и ее вложенных подразделов, если они появятся.

Актуальная структура каталога:

- `catalog/stretch-plenka`;
- `catalog/kleikaya-lenta`;
- `catalog/kleikaya-lenta/s-logotipom`;
- `catalog/kleikaya-lenta/s-logotipom/poverhnostnaya-pechat`;
- `catalog/kleikaya-lenta/s-logotipom/mezhsloynaya-pechat`;
- `catalog/kleikaya-lenta/malyarnaya-lenta`;
- `catalog/kleikaya-lenta/termostoykaya-malyarnaya`;
- `catalog/kleikaya-lenta/tpl`;
- `catalog/kleikaya-lenta/lenty-s-naneseniem`;
- `catalog/kleikaya-lenta/izolyatsionnaya-lenta`;
- `catalog/signalnye-lenty`.

Порядок блоков:

- хлебные крошки;
- `section.section`;
- `.container`;
- `.section-header`;
- один `h1` с названием раздела;
- описание раздела;
- `CategoryLinkList` со ссылками на подразделы;
- `.product-list` со всеми товарами раздела из всех подразделов.

На странице должен быть только один `h1`.

## Подразделы

Подразделы выводятся через компонент `CategoryLinkList`.

Каждый пункт:

- является ссылкой;
- ведет на страницу соответствующего подраздела;
- визуально выглядит как небольшой блок с бордером;
- содержит только название подраздела.

## Карточки товаров

Товары раздела выводятся через компонент `ProductItemCard`.

Карточка товара должна содержать:

- шапку карточки;
- ссылку на товар вокруг изображения или заглушки изображения;
- название товара;
- первые 5 характеристик списком в формате `название - значение`;
- стоимость в формате `От ... рублей/штука` или временное значение `От рублей/штука`, если цена еще не передана;
- кнопку `Подробнее`, ведущую на детальную страницу товара.

Название товара ограничивается двумя строками. Характеристики выводятся компактно: слева название характеристики, справа значение, шрифт 12px.

## Наполнение

Если клиент передал сырой текст, агент должен:

- определить название раздела;
- выделить описание раздела;
- определить список подразделов;
- определить `id`, `parentId` и `slug` раздела по текущей структуре каталога;
- собрать товары из всех подразделов в единый список;
- для каждого товара запросить недостающие данные: название, ссылку, изображение, характеристики в формате `label/value`, цену;
- если изображение отсутствует, оставить карточку с заглушкой;
- если цена отсутствует, использовать временное значение `От рублей/штука`.

Не нужно создавать разные шаблоны карточек под разные подразделы. Все товары раздела используют один компонент карточки.

## Объект товара

Товары добавляются в `src/content/catalog/products.js`. Карточка товара должна получать полный объект товара, а не отдельный набор разрозненных полей.

Обязательная структура:

- `id` - стабильный идентификатор товара;
- `title` - название товара;
- `parentId` - id раздела или подраздела, к которому относится товар;
- `slug` - slug товара;
- `href` - ссылка на будущую детальную страницу;
- `card` - данные для карточки в списке;
- `detail` - данные для будущей детальной страницы товара.

В `card` хранятся:

- `image`;
- `imageAlt`;
- `price`;
- `characteristics` - первые характеристики для карточки в формате `label/value`.

В `detail` заранее хранятся:

- `lead`;
- `description`;
- `gallery`;
- `specifications`;
- `advantages`;
- `order`;
- `seo`.

Даже если детальная страница еще не реализована, поля `detail` нужно создавать сразу, чтобы структура данных товара не менялась при следующем этапе.

## Детальная страница товара

Детальная страница товара создается тем же динамическим роутом `src/pages/catalog/[...slug].astro` на основе `href` товара.

Шаблон страницы:

- хлебные крошки;
- слева блок со слайдером `Slider`, даже если изображение одно;
- блок со слайдером на десктопе должен быть sticky;
- справа название товара, характеристики, цена и кнопка `Заказать`;
- ниже этих двух колонок детальное описание товара на всю ширину контентной области.

Кнопка `Заказать` на детальной странице ведет к сквозной форме заявки. В карточках товаров на страницах разделов кнопка должна называться `Подробнее` и вести на детальную страницу товара.

## Работа промптом

При добавлении раздела агент добавляет один объект в `categories.js`.

При удалении раздела агент должен:

- найти категорию по `id`;
- проверить, есть ли у нее дочерние категории;
- проверить, есть ли товары с `parentId`, равным `id` удаляемой категории;
- если дочерние категории или товары есть, явно сообщить об этом и не удалять молча.

При редактировании раздела агент меняет только нужные поля объекта категории. Если меняется `slug` или `parentId`, нужно проверить сборку и ссылки, потому что URL изменится автоматически.

При добавлении товара агент добавляет один объект в `products.js`, указывая `parentId` целевого раздела. При редактировании товара агент ищет его по `id`, затем меняет только нужные поля.

## Черновой импорт товаров

Для первичного сбора ассортимента из внешнего источника используется скрипт:

```bash
npm run catalog:import -- <url> --source=<name> --limit=40
```

Скрипт не добавляет товары на сайт напрямую. Он сохраняет черновик в `src/content/catalog/imports/<name>-draft.json`.

Для переноса проверенного draft в рабочий каталог используется нормализатор:

```bash
npm run catalog:normalize
```

Нормализатор читает все поддерживаемые draft-файлы из `src/content/catalog/imports`, создает `src/content/catalog/products.js`, убирает технические дубли, назначает `parentId`, строит `href`, оставляет только локальные изображения и формирует описания под Newmark.

Поддерживаемые source для текущих импортов:

- `arli-adhesive` - товары раздела `Клейкая лента`;
- `arli-stretch` - товары раздела `Стрейч-пленка`.

После импорта агент должен:

- проверить источник и количество найденных товаров;
- нормализовать характеристики;
- переписать описания под Newmark, не копируя тексты конкурента;
- назначить каждому товару `parentId` из нашей структуры каталога;
- перенести готовые объекты в подходящий файл товаров.

Правила нормализации:

- слово `скотч` в любом регистре не используется в публичном контенте сайта, вместо него пишем `клейкая лента`;
- если в названии товара есть `малярн`, товар относится к `parentId: "malyarnaya-lenta"`;
- если в названии товара есть `термостойк`, товар относится к `parentId: "termostoykaya-malyarnaya"`;
- если в названии товара есть `тпл` или источник указывает на сантехническую/монтажную ленту ТПЛ, товар относится к `parentId: "tpl"`;
- если в названии товара есть `изоляц`, товар относится к `parentId: "izolyatsionnaya-lenta"`;
- если в названии товара есть `логотип`, товар относится к `parentId: "poverhnostnaya-pechat"`, пока явно не указан другой тип печати;
- если в названии товара есть `нанес`, товар относится к `parentId: "lenty-s-naneseniem"`;
- если отдельного правила для товара пока нет, товар остается в общем разделе `parentId: "kleikaya-lenta"`;
- товары из source `arli-stretch` относятся к `parentId: "stretch-plenka"`;
- характеристика источника `Цена с НДС за коробку, руб` нормализуется как `Стоимость коробки с НДС`;
- цена в карточке пишется в формате `От ... рублей/штука`, сокращение `р/шт` не используется;
- если из-за пагинации или параметров URL импорт создал одинаковые товары, в рабочий каталог переносится только один товар;
- если импорт ошибочно распознал текстовую/SEO-страницу как товар, она не переносится в рабочий каталог. Признаки такой записи: слишком длинные значения характеристик, статья вместо коротких `label/value`, отсутствие нормального товарного набора параметров;
- изображения из внешнего источника скачиваются импортёром в `public/catalog/products/<source>/` и конвертируются в `.webp` без исходных метаданных;
- в рабочем товарном объекте `card.image` и `detail.gallery` должны ссылаться на локальный путь вида `/catalog/products/<source>/<file>.webp`;
- ссылки на сайт-источник не хранятся в рабочих товарных объектах, они допустимы только в draft для аудита импорта.
