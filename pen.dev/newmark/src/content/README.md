# Работа с контентом Newmark

Контент статичных страниц хранится в Markdown-файлах:

```text
src/content/pages/
```

Один файл равен одной странице сайта. Например:

```text
src/content/pages/about.md
```

Файлы, имя которых начинается с `_`, считаются черновиками или архивными версиями и не публикуются в маршрутах сайта.

## Базовый процесс

1. Клиент присылает обычный текст.
2. ИИ определяет семантику текста: заголовок, абзацы, списки, таблицы, ссылки, изображения, слайдеры.
3. ИИ приводит текст к Markdown-формату.
4. ИИ сохраняет страницу в `src/content/pages/`.
5. Проект собирается и проверяется через `npm run build`.

## Frontmatter

В начале файла обязательно указывается frontmatter:

```md
---
slug: about
title: О компании
seoTitle: О компании НьюМарк
seoDescription: Краткое описание страницы для поисковых систем.
breadcrumbs:
  - label: Главная
    href: /
  - label: О компании
---
```

Правила:

- `slug` формирует URL страницы;
- `title` используется как внутреннее название;
- `seoTitle` попадает в тег `title`;
- `seoDescription` попадает в `meta description`;
- `breadcrumbs` задают хлебные крошки;
- первый Markdown-заголовок `#` является единственным `h1` страницы.

## Заголовки

```md
# Главный заголовок страницы

## Раздел страницы

### Подраздел
```

На странице может быть только один `#`.

## Абзацы

Абзацы пишутся обычным текстом и разделяются пустой строкой:

```md
Первый абзац.

Второй абзац.
```

## Списки

Маркированный список:

```md
- первый пункт;
- второй пункт;
- третий пункт.
```

Нумерованный список:

```md
1. Первый шаг.
2. Второй шаг.
3. Третий шаг.
```

## Ссылки

```md
[Контакты](/contacts/)
```

## Изображения

```md
![Описание изображения](/images/example.webp)
```

У каждого изображения должен быть осмысленный `alt`.

## Таблицы

```md
| Поле | Значение |
| --- | --- |
| Ширина | 48 мм |
| Цвет | прозрачный |
```

## Цитаты

```md
> Важное уточнение или выдержка.
```

## Разделитель

Для явного смыслового разделения используется Markdown-разделитель:

```md
---
```

Он рендерится как `hr`.

## Слайдер

Слайдер задается в два шага.

Сначала во frontmatter описывается набор изображений:

```md
---
sliders:
  production:
    - src: about-slide-1.webp
      alt: Производственная линия
    - src: about-slide-2.webp
      alt: Ассортимент продукции
---
```

Затем в контенте ставится шорткод:

```md
{{ slider: production }}
```

Правила:

- `src` указывает имя файла из `src/images/webp/`;
- изображения для слайдера готовятся в размере или пропорции 400x300;
- у каждого изображения должен быть `alt`;
- слайдер является визуальной сущностью контента и располагается в потоке Markdown;
- слайдер должен оставаться внутри общего контейнера страницы;
- один слайд не должен быть шире 400px.

## Что нельзя делать

- Не создавать JSON-структуры для статичных страниц.
- Не добавлять в Markdown HTML-разметку без необходимости.
- Не добавлять второй заголовок `#`.
- Не дублировать сквозную форму заявки в контенте страницы.
- Не использовать декоративные классы внутри Markdown.
