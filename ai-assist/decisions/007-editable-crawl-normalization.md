# ADR-007: сохраняемый сырой текст и редактируемая ИИ-нормализация

- Статус: принято
- Дата: 2026-09-15
- Дополняет: [ADR-005](005-ai-normalized-raw-site-ingestion.md)

## Контекст

Первоначальный URL-ingestion сразу передавал извлечённый `body.text()` модели и сохранял только
нормализованную запись. Это не позволяло скорректировать инструкцию после обхода без повторного
запроса сайта. Кроме того, технические `script` и `style` занимали лимит входного текста и могли
вытеснить видимое описание товара до вызова модели.

Главная цель нормализации — создать достоверную и максимально полную запись по всем относящимся к
основному предмету страницы фактам. Сокращение полезного описания не является очисткой мусора.

## Решение

1. HTML-extractor удаляет только невидимые технические узлы `script`, `style`, `noscript`,
   `template` и `svg`. Меню, footer, баннеры, повторяющиеся блоки и прочий видимый текст остаются
   входом ИИ-нормализации.
2. Лимит видимого сырого текста увеличен до 120 000 символов. Защитные лимиты HTTP-ответа и
   provider-вызова сохраняются.
3. Успешно извлечённые заголовок и сырой текст сохраняются в page result. Raw HTML не хранится и
   через административный API не возвращается.
4. Каждый crawl run хранит неизменяемый снимок операторского prompt-а. В форме нового источника его
   можно изменить до технического обхода.
5. После завершения run оператор может изменить prompt и запустить новую ИИ-обработку сохранённых
   страниц. Создаётся отдельный run; сайт повторно не запрашивается, прежний результат не
   переписывается.
6. Редактируемая инструкция отделена от неизменяемой safety policy. Оператор не может разрешить
   выполнение инструкций страницы, генерацию отсутствующих фактов или произвольный формат ответа.
7. Prompt по умолчанию требует сохранить без резюмирования все уникальные относящиеся к странице
   описания, свойства, ограничения, цены, наличие и условия, удаляя только повторы и нерелевантный
   контекст.

## Следствия

- Оператор может подбирать правила полноты и очистки без повторной нагрузки на сайт.
- Каждый вариант нормализации имеет собственные run/results и audit provenance.
- База хранит сырой видимый текст, поэтому для production нужна явная retention-политика crawl
  snapshots; опубликованный Markdown по-прежнему живёт по lifecycle документа.
- Очень большие страницы всё ещё ограничены защитным пределом входа, а одна страница создаёт одну
  запись. Разбиение одной страницы на несколько сущностей остаётся отдельным расширением.
