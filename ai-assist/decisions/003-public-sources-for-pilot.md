# ADR-003: только публичные источники для первого pilot

- Статус: принято; решение о переносе файлов за пределы pilot частично заменено ADR-004
- Дата: 2026-09-02
- Первый проект: `https://gofroprodpak.ru/`
- Уточняет ADR-002 для первого pilot; файловая часть уточнена ADR-004

## Контекст

Прямое подключение AI Assist к рабочей базе данных магазина увеличивает поверхность атаки и последствия ошибки конфигурации. Даже read-only учетная запись может открыть служебную структуру, персональные данные или создать нежелательную нагрузку на production. Для первого запуска эта сложность не оправдана: каталог и общая информация уже доступны на публичном сайте.

## Решение для MVP

- AI Assist не подключается к MySQL или другой рабочей БД клиента.
- Не запрашиваем и не храним реквизиты БД, VPN, SSH-туннеля или приватного API магазина.
- Автоматические знания получаем плановым SSRF-safe обходом разрешенных публичных HTTPS-страниц и, если доступен, публичного feed URL.
- Ручные статьи и карточки товара допускаются через административную панель.
- Обход не выполняется на каждое сообщение. Worker создает версионируемый draft, после проверки публикуется новый индекс.
- Цена, наличие и другие изменяемые значения сопровождаются временем последней синхронизации. Ассистент не называет их данными в реальном времени и при необходимости дает ссылку на карточку товара.

Первоначально активный контракт источников MVP был ограничен типами `url`, `feed`, `manual` и `product`. ADR-004 добавил защищённую загрузку файлов администратором в scope первого pilot; запрет `mysql` и `api` не изменён.

## Отложенные возможности

После стабилизации pilot планируется:

1. первоначально здесь находилась загрузка XML/YML/CSV-файлов; ADR-004 перенёс защищённый admin file ingestion в первый pilot;
2. исследование импорта каталога из БД как отдельной интеграции;
3. security review и отдельный ADR до появления любых реквизитов или сетевого доступа к БД.

Если импорт из БД будет одобрен, модель и chat runtime все равно не получат доступ к соединению и не будут создавать SQL. Изолированный ingestion-worker сможет только выгрузить ограниченный нормализованный снимок через фиксированный versioned adapter. Снимок пройдет pipeline `draft → validation/diff → publication → retrieval`; подключение к primary production database по умолчанию запрещено.

## Следствия

- Первый pilot можно разработать и принять без доступа к инфраструктуре клиента.
- Риск утечки реквизитов и нагрузки на production БД исключается из MVP.
- Актуальность каталога зависит от расписания crawl/feed и отображается пользователю явно.
- ADR-002 остается историей исходного рассмотрения гибридных источников, но его MySQL/API-варианты не входят в активный scope pilot.
