# ADR-002: гибридная база знаний и источники каталога

- Статус: частично заменено ADR-003 для первого pilot
- Дата: 2026-09-01
- Первый проект: `https://gofroprodpak.ru/`

> Решение о MySQL/API ниже сохранено как история первоначального проектирования. Для первого pilot действует [ADR-003](003-public-sources-for-pilot.md): только публичный crawl/feed и ручные данные, без реквизитов и сетевого доступа к БД клиента.

## Контекст

Ассистенту нужны два класса данных:

1. стабильные сведения — названия, SKU, категории, характеристики, описания, доставка и общая информация о компании;
2. оперативные сведения — цена, наличие, минимальная партия и срок изготовления.

Полный обход публичного сайта на каждый вопрос медленный, плохо предсказуемый и создает лишнюю нагрузку. Один только периодический HTML-парсинг, напротив, может временно показывать устаревшую цену. Для Bitrix-магазина дополнительно возможен структурированный источник MySQL.

## Решение

Используем гибридную схему:

- стабильные данные периодически синхронизируются в версионируемую БЗ AI Assist и индексируются для поиска;
- перед ответом об изменяемых данных выполняется точечная проверка только выбранных товаров через безопасный live-адаптер;
- ответ содержит время актуальности и provenance источника;
- при недоступности live-источника ассистент явно сообщает, что показывает последнее синхронизированное значение.

Поддерживаемые стратегии, выбор которых зависит от доступов клиента:

1. базовый путь MVP: YML/XML/CSV-фид, если он есть, и плановый HTML-ingestion;
2. опциональный structured source: отдельный read-only API магазина;
3. опциональный structured source: read-only реплика MySQL либо отдельный пользователь MySQL с `SELECT` только на разрешенные представления;
4. точечное чтение публичной карточки товара как проверка фактически отображаемого значения.

Ни MySQL, ни прямой API магазина не являются обязательными для запуска ассистента. Подключение любого нового источника не меняет общий pipeline draft → validation → publication → retrieval.

## Ограничения MySQL-коннектора

- Предпочтителен не доступ к primary production database, а replica или специально подготовленные SQL views.
- Учетная запись не имеет `INSERT`, `UPDATE`, `DELETE`, DDL, `FILE`, administrative и replication privileges.
- Сетевой доступ ограничивается адресом worker/VPN и TLS; MySQL не публикуется в интернет для ассистента.
- Пароль хранится только в зашифрованном credential store. Он не попадает в job payload, prompt, журналы или браузер.
- Модель не генерирует и не исполняет SQL. Запросы задаются версионируемым adapter profile, параметризуются и имеют timeout/row limit.
- Разрешенные таблицы, views, колонки и типы проверяются при настройке. Остальные данные, включая пользователей и заказы, недоступны.
- Первичная синхронизация и incremental sync работают в worker, а не в chat request.
- Live-check использует только фиксированный lookup по SKU/external id и возвращает ограниченный DTO.

## Почему не live-crawl на каждый вопрос

- ответ зависит от скорости и доступности чужого HTML;
- поиск по всему каталогу потребовал бы много запросов на одно сообщение;
- динамические фильтры, дубли URL и изменения верстки ухудшают качество;
- повышаются SSRF, prompt-injection и rate-limit риски;
- невозможно надежно воспроизвести, какой набор данных использовал конкретный ответ.

## Отказоустойчивость

- Последний успешно опубликованный индекс остается активным при ошибке очередной синхронизации.
- Новая версия проходит валидацию и активируется атомарно.
- Ошибка live-check не блокирует весь ответ, если есть достаточно стабильных данных.
- Цена и наличие без успешной проверки маркируются как данные на момент последней синхронизации.

## Следствия

- `knowledge_sources` поддерживает типы `mysql`, `api`, `feed`, `url`, `manual` и `product`.
- Нужны connector profiles, field mapping, incremental cursor и журнал синхронизации.
- HTML-парсер Newmark остается fallback и источником extraction rules, но не становится единственным production-каналом.
- MySQL adapter реализуется отдельным опциональным этапом при наличии согласованного доступа; основной runtime не импортирует его как обязательную зависимость.
