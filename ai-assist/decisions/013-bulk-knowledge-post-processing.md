# ADR-013: Массовая постобработка записей базы знаний

## Статус

Принято, 2026-09-17.

## Контекст

После технического парсинга отдельные записи могут содержать повторяющиеся, нерелевантные для БЗ
фрагменты. Ручное редактирование сотен записей непрактично, но скрытая автоматическая замена уже
опубликованного контента создаёт риск незаметно изменить production retrieval.

## Решение

- Оператор задаёт одну текстовую инструкцию и выбирает записи либо scope `all`.
- API фиксирует точные исходные version ids и ставит `knowledge.processing` в BullMQ.
- Worker применяет инструкцию к каждой записи независимо, сохраняет подтверждённые факты и не
  использует внешние источники.
- Результат сохраняется новой immutable version. `active_version_id` не меняется автоматически.
- Один проект имеет максимум один активный processing run; crawl и index build считаются
  конфликтующими операциями.
- Item-level ошибка не отменяет успешные результаты других записей; итоговый статус может быть
  `partial`.

## Последствия

Опубликованные ответы остаются стабильными до явной публикации оператором, а новая версия доступна
для проверки. За это приходится платить дополнительными версиями и отдельным progress state, зато
операция восстанавливается после перезапуска worker-а и сохраняет аудит исходной инструкции.
