# ADR-016: Повторы ошибочных записей постобработки

## Статус

Принято, 2026-09-18.

## Контекст

Массовая AI-постобработка сотен записей может частично завершиться ошибками из-за временной
недоступности provider-а, timeout или некорректного ответа модели. Ранее каждая запись выполнялась
один раз, поэтому кратковременный сбой оставлял значительную часть run в `failed`, а оператор мог
только повторно обработать всю базу.

## Решение

- Каждый `knowledge_processing_item` хранит durable `attempt_count`.
- Worker оставляет item в `queued` и повторяет временные коды ошибок с ограниченной
  экспоненциальной задержкой. Общий предел — три item-level попытки.
- Постоянные ошибки завершают item сразу. Progress run увеличивается только при окончательном
  `succeeded|failed`, поэтому повтор не считается новой записью.
- Pause, stop и восстановление BullMQ job учитываются между раундами; сохранённый `attempt_count`
  не позволяет сбросить лимит после рестарта worker-а.
- Для терминального `partial|failed` run оператор может создать новый run только по failed document
  ids. Сервер повторно выбирает доступные документы и их актуальные versions, сохраняет исходную
  инструкцию и не затрагивает уже успешные items.

## Последствия

Кратковременные ошибки исправляются автоматически без повторной обработки успешных записей.
Оставшиеся ошибки можно доделать одним явным действием, сохранив отдельную историю запуска и
ограничив бесконечные повторы.
