# ADR-005: сырой HTML-ingestion с AI-нормализацией

- Статус: принято
- Дата: 2026-09-15
- Заменяет extraction-часть ADR-002 и прежние правила HTML-crawler из этапа 6

## Контекст

Разные магазины не гарантируют schema.org, JSON-LD, одинаковые DOM-selectors или фиксированный набор
товарных полей. Поддержка отдельных structured extractors делает подключение каждого сайта дорогим и
оставляет в интерфейсе лишнюю для оператора модель товарных полей и черновых версий.

## Решение

1. Для URL-источника администратор задаёт публичный URL и глубину структуры.
2. Discovery объединяет sitemap и навигационные меню главной страницы в полное вложенное дерево до
   заданного уровня. Оператор выбирает точные узлы или узлы вместе с потомками.
3. Crawler выполняет только SSRF-safe fetch и сырой HTML-to-text без schema.org/JSON-LD/microdata
   classification и без удаления boilerplate.
4. Worker передаёт сырой текст отдельному server-side AITUNNEL chat-вызову. Источник считается
   недоверенным user content. Фиксированная platform-инструкция требует удалить мусор, не добавлять
   факты, выбрать `info|product|service` и вернуть один JSON-объект с title и Markdown.
5. Provider output проходит строгую runtime-схему. Ошибка модели/схемы даёт page-level failure и не
   создаёт знание.
6. Все свойства товара, цена, артикул и условия остаются внутри Markdown. Новые structured
   `knowledge_products` rows crawler не заполняет содержательными значениями.
7. UI записи показывает только название, тип, Markdown и URL источника. История immutable versions
   остаётся внутренним механизмом аудита/конкурентности, но не является пользовательским workflow:
   изменение и активация выполняются одной кнопкой «Опубликовать изменения»; отдельно доступно
   «Снять с публикации».

## Границы безопасности

- AI-normalizer не получает tools, credentials, system prompt ассистента или доступ к сети.
- Сырой текст сайта не интерполируется в system message и не может изменить platform-инструкцию.
- Модель не публикует результат автоматически: crawl result остаётся на ручном подтверждении.
- URL/DNS/redirect/robots/MIME/size/time limits прежнего crawler сохраняются.
- Для запуска необходимы verified provider credential и выбранная chat-модель проекта.

## Следствия

- Качество результата теперь зависит от chat-модели и требует page-level review.
- Один model request выполняется на одну успешно загруженную страницу; стоимость и latency растут
  пропорционально числу страниц.
- Страница создаёт одну запись БЗ. Разделение одной страницы на несколько сущностей остаётся будущим
  расширением.
- JS-rendering, file/feed ingestion, missing detection, расписание и автоматический reindex после
  ручного редактирования не входят в это изменение.
