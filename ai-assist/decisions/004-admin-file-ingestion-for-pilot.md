# ADR-004: загрузка файлов администратором в первом pilot

- Статус: принято
- Дата: 2026-09-02
- Первый проект: `https://gofroprodpak.ru/`
- Уточняет ADR-003 в части файлов; запрет прямого доступа к рабочей БД сохраняется

## Контекст

Часть подтверждённых знаний и каталожных данных может существовать только в документах и выгрузках владельца: TXT, PDF, Word, Excel, CSV, XML/YML. Ручное копирование каждого товара в поле текста не масштабируется и повышает риск ошибок. Администратору нужен единый импорт, который автоматически распознаёт структуру, заполняет черновики и оставляет человеку понятное подтверждение результата.

## Решение

Загрузка файлов администратором входит в scope первого pilot как отдельный source adapter `file`. Это не загрузка файлов посетителем в чат и не прямой доступ модели к файловой системе.

Первая очередь форматов:

- plain text: `.txt`, `.md`;
- документы: `.pdf` с текстовым слоем, `.docx`;
- таблицы/каталоги: `.csv`, `.xlsx`;
- товарные выгрузки: `.xml`, `.yml`.

Сканированные PDF/изображения с OCR, legacy `.doc`/`.xls`, защищённые паролем документы, файлы с макросами и архивы не входят в первую очередь. `.docm`/`.xlsm` отклоняются. Дополнительный формат включается только после parser fixture, resource-limit и security-тестов.

Пользовательский happy path:

1. Owner/Editor загружает файл и задаёт название импорта.
2. Система проверяет signature/MIME/размер, сохраняет оригинал в закрытом object storage и ставит ingestion job в очередь.
3. Детерминированный parser извлекает текст, листы, строки и базовую структуру без выполнения макросов, JavaScript, внешних ссылок или embedded objects.
4. AI-assisted mapper классифицирует содержимое и предлагает manual documents либо product rows со structured fields, provenance и confidence. Он не публикует данные и не получает tools/secrets.
5. Интерфейс показывает сводку, ошибки, сомнительные поля и diff. В нормальном случае администратор только подтверждает импорт; при low confidence/conflict доступно исправление исключений.
6. Подтверждение создаёт/обновляет draft document versions. Отдельная публикация активирует выбранный batch/index version.

Требование «задать название и подтвердить» является целевым happy path, но не основанием скрывать ошибки распознавания. Цена, наличие, SKU и другие значимые поля с низкой уверенностью требуют явного внимания.

## Представление больших каталогов

Каталог не отображается одним гигантским полем «Подтверждённый текст». Основной интерфейс — импорт/batch и пагинированная таблица товаров с фильтрами по статусу, категории, наличию, confidence и типу изменения. Карточка товара показывает структурированные поля, исходный фрагмент и provenance. Нормализованный retrieval text генерируется системой и доступен в дополнительном техническом preview, но не является главным редактором каталога.

Для обычного текстового документа остаётся секционный preview извлечённого текста. Для книги/многостраничного PDF система создаёт несколько логических документов или разделов, а не одну неуправляемую запись.

## Retrieval

Файлы и crawler проходят один pipeline документов, chunks и публикаций. Для большого каталога используется hybrid retrieval в PostgreSQL:

- structured/exact lookup для SKU, external id, цены, категории и фильтров;
- PostgreSQL full-text/trigram для названий и точных терминов;
- `pgvector` для смысловой близости естественного вопроса и chunks;
- опциональный rerank только после измерения качества/latency.

Отдельная специализированная vector database в pilot не вводится. PostgreSQL + pgvector уже находится в инфраструктуре и сохраняет tenant filtering, backup и publication consistency в одном контуре. Внешняя vector DB рассматривается только при доказанном ограничении объёма или latency.

## Безопасность и ограничения

- upload требует admin session, Editor/Owner role, CSRF, quotas и rate limits;
- формат определяется по signature и безопасному parser-у, а не только расширению;
- обязательны защита от zip/XML bombs, DTD/XXE, path traversal, oversized sheets/pages/cells и parser timeout;
- оригинал приватный, имеет checksum/retention и никогда не раздаётся по публичному URL;
- извлечённый текст считается недоверенным и не может менять prompt/platform policy;
- publish только ручной; удаление файла не должно незаметно удалить уже опубликованные знания;
- прямой доступ к рабочей БД, VPN, SSH и приватному API остаётся вне pilot.

## Следствия

- File adapter и public crawler используют общие ingestion jobs, review/diff, document versions, chunks и index activation.
- Нужно добавить upload/import batch entities, object storage adapter, безопасные parsers и отдельный каталоговый интерфейс.
- Текущий API до реализации новых endpoints продолжает отклонять `file`; это временное состояние реализации, а не граница утверждённого pilot scope.
