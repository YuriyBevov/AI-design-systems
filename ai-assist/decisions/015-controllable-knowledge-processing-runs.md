# ADR-015: Управляемые запуски постобработки базы знаний

## Статус

Принято, 2026-09-18.

## Контекст

Массовая AI-постобработка может занимать часы и обращаться к сотням записей. Единственного статуса
последнего запуска недостаточно: оператору нужны история, безопасная пауза, кооперативная остановка
и удаление завершённых технических запусков без удаления созданных версий БЗ.

## Решение

- `knowledge_processing_runs` хранит `pause_requested_at` и терминальный статус `cancelled`.
- Пауза не прерывает уже начатые provider-запросы, но worker не начинает новые items до продолжения.
- Остановка доступна для queued/running run независимо от паузы: API переводит его в `cancelled`,
  worker подтверждает завершение через `finished_at`, а необработанные items остаются техническими
  данными остановленного запуска.
- Удалять можно только терминальный запуск. Каскад удаляет processing items и BullMQ job, но не
  созданные immutable document versions.
- GET коллекции возвращает до 5 000 запусков текущего проекта в обратном хронологическом порядке.
- Все мутации требуют Editor/Owner, CSRF, tenant scope и создают audit events.

## Последствия

Оператор видит полную историю и может управлять долгой задачей без потери уже созданных результатов.
Остановка остаётся кооперативной: между нажатием и подтверждением worker-а могут завершиться уже
выполняющиеся запросы к модели.
