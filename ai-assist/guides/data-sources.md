# Источники данных каталога

## 1. Граница первого pilot

Первый pilot работает без доступа к рабочей БД, приватному API, VPN или SSH магазина. AI Assist не запрашивает и не хранит такие реквизиты. Разрешены только:

- плановый обход публичных HTTPS-страниц в подтвержденной области сайта;
- публичный URL XML/YML/CSV-фида, если он существует;
- поддерживаемые файлы, которые Owner/Editor явно загрузил через административную панель;
- ручные статьи и карточки товара из административной панели.

Целевой контракт первого pilot: `url | feed | file | manual | product`. Текущий реализованный документный API пока принимает только `manual|product`, а source/upload endpoints ещё не реализованы. Значения `mysql` и `api` остаются запрещёнными в pilot; `file` нельзя включать частично до завершения всего защищённого flow из ADR-004.

Каждый источник возвращает нормализованные записи и provenance. Он не пишет напрямую в опубликованный индекс: worker сначала создает draft-версию, валидирует ее, показывает diff и только затем атомарно публикует.

## 2. Публичный сайт

HTML-ingestion используется для товарных карточек, категорий и общей информации о компании. Полный обход запускается по расписанию или администратором, но не на каждое сообщение пользователя.

- URL проходит SSRF-проверку до сохранения и перед каждым запросом/redirect.
- Crawler соблюдает разрешенный host/path scope, robots policy, rate limit, timeout и лимит размера ответа.
- Приоритет extraction: JSON-LD → семантическая разметка → versioned site profile → безопасный generic extractor.
- Исходный HTML считается недоверенным контентом и не может менять system prompt.
- Низкая confidence, обязательные отсутствующие поля или резкое изменение количества товаров переводят импорт в review.
- Цена, наличие и срок сопровождаются временем последней успешной синхронизации и canonical URL.

Точечная проверка изменяемого значения может читать только публичную карточку уже найденного товара по нормализованному SKU/external id. Она ограничена по времени и числу запросов; при ошибке используется последнее опубликованное значение с явным указанием его даты.

## 3. Публичный feed URL

XML/YML/CSV-фид по публичному HTTPS URL является вторым вариантом MVP. Сохраняются checksum, дата получения, версия mapping profile и ошибки отдельных строк. Фид нельзя считать свежим после истечения настроенного freshness SLA.

Даже публичный feed обрабатывается как недоверенный ввод:

- ограничиваются размер, время загрузки, redirects и MIME;
- XML parser не разрешает DTD и внешние сущности;
- глубина, число элементов, длина текстовых полей и количество ошибок bounded;
- URL товаров и изображений нормализуются и повторно проходят policy;
- публикация выполняется только после schema validation и diff.

## 4. Приоритет полей в pilot

| Поле                             | Основной источник         | Fallback                          |
| -------------------------------- | ------------------------- | --------------------------------- |
| SKU, название, характеристики    | feed или карточка товара  | ручная карточка                   |
| цена и ступени количества        | feed или карточка товара  | последнее опубликованное значение |
| наличие/статус производства      | публичная карточка товара | значение с датой синхронизации    |
| описание категории               | публичная страница        | ручная статья                     |
| доставка и информация о компании | публичная страница        | ручная статья                     |

При конфликте значения не склеиваются молча. Mapping profile задает приоритет, ingestion записывает conflict event, а опубликованная запись сохраняет provenance и время актуальности.

## 5. Загрузка файлов администратором

File ingestion входит в первый pilot как отдельный source type `file`. Первая очередь: TXT/Markdown, PDF с текстовым слоем, DOCX, CSV/XLSX и XML/YML. Сканированные PDF/OCR, legacy DOC/XLS, macro-enabled и password-protected файлы отложены. До готовности всего защищённого flow тип `file` вообще не принимается API.

Нормальный сценарий: администратор загружает файл и задаёт название импорта; система автоматически определяет структуру, предлагает manual documents или structured product rows и показывает сводку/confidence/diff; пользователь подтверждает batch. Редактирование требуется только для ошибок, конфликтов и low-confidence полей.

Обязательные свойства flow:

- allowlist форматов и проверка content signature, а не только расширения;
- лимит размера, строк/элементов, глубины XML и времени разбора;
- запрет DTD, внешних сущностей, сетевых обращений и исполняемого содержимого;
- хранение оригинала в закрытом object storage с retention и checksum;
- versioned mapping, preview, validation report и diff;
- ручная публикация и возможность вернуть предыдущую index version.

Большой каталог показывается как import batch и пагинированная таблица, а не как одно поле «Подтверждённый текст». Основные колонки: товар, SKU/external id, category, price, availability, status/confidence и изменение `new|changed|unchanged|missing|conflict|failed`. Детальная карточка показывает structured fields, исходный fragment и provenance; нормализованный retrieval text доступен только в дополнительном preview.

## 6. Будущее исследование импорта из БД

DB import не входит в pilot. До его разработки нужны threat model, security review и новый ADR. Рассматривается именно скачивание ограниченного снимка каталога изолированным ingestion-worker, а не доступ агента к БД во время ответа.

Минимальные неизменяемые границы:

- LLM, prompt pipeline, widget и chat runtime не получают connection string, schema или SQL-инструмент;
- primary production database не является допустимым target по умолчанию;
- предпочтителен подготовленный export/replica либо отдельные versioned views без заказов, пользователей и персональных данных;
- только фиксированные параметризованные запросы с allowlist, timeout, row/batch limits и read-only transaction;
- реквизиты вводятся владельцем только в защищенную форму и не передаются в чат разработки;
- полученный snapshot проходит тот же `draft → validation/diff → publication → retrieval` pipeline;
- сетевой доступ существует только на время ingestion job и закрыт для public/chat API.

Без отдельного одобрения этих условий реализация DB-коннектора не начинается.
