# Руководство администратора

## 1. Первоначальная настройка проекта

1. Войти как Администратор, при необходимости создать пользователей, затем создать или открыть проект.
2. Проверить timezone, locale и срок хранения диалогов.
3. На странице «Ассистент» проверить публичный id, внешний вид, fallback/лимиты и добавить точные Origins production/preview сайтов; сохранить черновик.
4. Подключить AITUNNEL key по provider guide.
5. Синхронизировать модели и выбрать chat + embedding model.
6. Создать system prompt revision, прогнать базовый preview и опубликовать.
7. Добавить несколько ручных контрольных документов/товаров.
8. При наличии файла загрузить его как отдельный import, проверить автоматически распознанные документы/товары, confidence и ошибки.
9. Проверить retrieval/playground.
10. В URL source получить структуру сайта, отметить разделы первого уровня и для каждого решить, включать ли внутренние страницы; выбрать быстрый либо полный режим и проверить общий лимит страниц. Подсказка `?` над каждым параметром объясняет его действие.
11. В результате обхода отметить нужные строки или выбрать все, массово опубликовать знания и повторно прогнать eval.
12. Скопировать embed snippet, установить на staging сайта.
13. Пройти widget/Bitrix/CSP проверки, затем включить production Origin и виджет.

Сейчас в панели реализованы две продуктовые роли. Администратор имеет полный доступ ко всем проектам и управляет учетными записями в разделе «Пользователи». Пользователь видит только назначенные проекты в режиме чтения без технического раздела «Компоненты». Участников можно назначить при создании проекта или позднее в карточке пользователя.

В панели реализованы создание prompt, metadata, версии, проверка переменных, model preview, публикация, rollback, archive и безопасное удаление неиспользованного draft. Настройки ассистента и Origins также версионируются: сначала сохраняется черновик, затем Администратор отдельно публикует его вместе с активными prompt/model snapshots. В разделе «База знаний» доступны ручные документы/товары, immutable versions, publish/unpublish/archive/delete. Раздел «Источники сайта» перед запуском показывает объединённую sitemap/navigation структуру первого уровня, позволяет выбрать точные либо рекурсивные разделы и быстрый/полный режим. Полный обход выполняется worker-ом до исчерпания найденных URL или защитного лимита 5000, показывает прогресс и пагинированные результаты. Публикация может затронуть отмеченные чекбоксами строки либо все готовые черновики запуска. Preview использует выбранную prompt revision, draft-конфигурацию, текущую chat-модель и только опубликованные знания проекта/локали; он расходует provider budget, но не меняет production.

## 2. Ежедневная/регулярная работа

- Проверять failed/partial crawl jobs и freshness.
- Просматривать no-result rate и частые темы без ответа.
- Следить за provider balance/budget, error rate и стоимостью.
- Проверять новые/changed/missing документы перед публикацией.
- Обновлять eval-набор при появлении реального неудачного вопроса.
- Не менять одновременно prompt, модель и большую часть базы без раздельных preview: иначе причину изменения качества нельзя определить.

## 3. Безопасное изменение

Рекомендуемая последовательность:

1. Создать draft.
2. Записать цель изменения.
3. Прогнать релевантный eval + regression set.
4. Просмотреть sources, cost и latency.
5. Опубликовать одно логическое изменение.
6. Наблюдать pilot metrics.
7. При ухудшении выполнить rollback publication.

## 4. Сценарии проблем

### Ассистент выдумывает факт

1. Сохранить request/run id и точный вопрос.
2. Проверить retrieved chunks/provenance.
3. Если факт есть неверно — исправить/снять документ и reindex.
4. Если факта нет — добавить кейс в eval и проверить threshold/fallback/prompt.
5. Не исправлять единичный факт добавлением его в system prompt.

### Не находится существующий товар

Проверить document published status, active index, locale, product identity, chunks, query spelling, vector/full-text ranks. Затем исправлять extraction/chunking/retrieval и добавлять regression case.

### Парсер стал извлекать меньше товаров

Сравнить source HTML/profile version, robots/sitemap, job errors и changed/missing diff. Missing items не удалять массово до подтверждения изменения сайта.

### Provider недоступен

Проверить credential status, provider status/error code, balance/budget, model availability. Не публиковать другой model без eval. Widget должен показывать безопасный fallback.

### Ключ мог быть раскрыт

1. Немедленно отозвать ключ в AITUNNEL.
2. Удалить/заменить credential в AI Assist.
3. Зафиксировать incident time/scope.
4. Проверить audit/logs/deploy artifacts без копирования секрета.
5. Создать новый ограниченный по бюджету ключ.
6. Устранить канал раскрытия и пройти incident review.

## 5. Удаление

- Unpublish — прекратить использование, сохранить возможность review/rollback.
- Archive — вывести сущность из рабочего списка/runtime.
- Purge — необратимо удалить по retention/правовому запросу; требует Администратора, inventory и отдельного подтверждения.

Перед purge администратор должен увидеть связанные documents/chunks/conversations/objects/audit limitations.

## 6. Перед включением production

- [ ] Key masked/verified, budget limits заданы.
- [ ] Chat/embedding модели доступны.
- [ ] Prompt и знания опубликованы осознанно.
- [ ] Eval/fallback/prompt-injection cases пройдены.
- [ ] Origins точные, wildcard отсутствует.
- [ ] Widget проверен на staging Bitrix/host CSS/mobile/a11y.
- [ ] Consent/privacy/retention подтверждены владельцем и юристом при необходимости.
- [ ] Alerts, backup и rollback готовы.
- [ ] Контакт поддержки/fallback виден пользователю.
