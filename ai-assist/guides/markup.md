# Правила HTML/Vue-разметки

Документ переносит правила разметки Newmark в Nuxt-панель и встраиваемый Vue-виджет AI Assist. Исходная база: [`guides/html.md`](../../guides/html.md) и общие ограничения [`guides/agent.md`](../../guides/agent.md).

Правила именования находятся в [class-names.md](class-names.md).

## 1. Основной принцип

Разметка описывает смысл, структуру и взаимодействие, а не внешний вид. Она должна:

- читаться и оставаться понятной без CSS;
- использовать нативную HTML-семантику;
- состоять из переносимых компонентов;
- не повторять CSS-логику лишними обертками;
- быть доступной с клавиатуры и для assistive technologies;
- оставаться устойчивой на мобильном экране;
- безопасно отображать недоверенные данные.

Сначала определить области, компоненты и отношения контента, затем писать шаблон. Декоративные контейнеры не являются стартовой структурой.

## 2. Теги по назначению

- `main` — основное содержимое страницы панели; один на документ.
- `header` — вводная область страницы/компонента, если это семантически оправдано.
- `nav` — набор навигационных ссылок с доступным именем.
- `section` — именованная смысловая секция, обычно с заголовком.
- `article` — самостоятельная запись/карточка, которая имеет смысл отдельно.
- `aside` — дополнительная, а не просто визуально боковая область.
- `ul`/`ol` — реальные списки, включая список сообщений/ошибок/источников.
- `table` — табличные данные, а не grid из `div`.
- `button` — действие на текущей странице.
- `a` — переход по URL.
- `form`, `label`, `fieldset`, `legend` — формы и группы полей.

Не использовать `div`/`span` как кнопку или ссылку с `@click`.

```vue
<!-- Плохо -->
<div class="button" @click="publishPrompt">Опубликовать</div>

<!-- Хорошо -->
<button class="button button--primary" type="button" @click="publishPrompt">
  Опубликовать
</button>
```

## 3. Каркас административной страницы

Типовой Nuxt layout содержит общий `app-shell`, а каждая route page — собственный заголовок и смысловые секции.

```vue
<main class="app-shell__main">
  <header class="page-header">
    <div>
      <h1 class="page-title">Настройки провайдера</h1>
      <p class="page-description">Подключение AITUNNEL и выбор моделей</p>
    </div>
    <div class="button-row page-actions">...</div>
  </header>

  <section class="form-section" aria-labelledby="credential-title">
    <div class="section-header">
      <h2 id="credential-title" class="section-title">API-ключ</h2>
    </div>
    ...
  </section>
</main>
```

Не добавлять глобальные `page-wrapper/content-wrapper`, если layout уже задает эту роль.

## 4. Заголовки

- На route page — один `h1`.
- Крупные секции — `h2`.
- Для сложной административной страницы допустим `h3` и глубже, только если это настоящая вложенная смысловая иерархия, а не выбор размера шрифта.
- В простых публичных/маркетинговых страницах сохраняется правило Newmark: `h1` + `h2`, локальные названия карточек — обычный текстовый элемент.
- Уровни нельзя пропускать ради визуального вида.
- Заголовок существует только при наличии реального видимого заголовка в ТЗ/дизайне/продуктовой структуре.
- Имя frame/layer/группы не превращается в заголовок.

Размер и капс задаются CSS. Текст, визуально набранный uppercase, хранится в обычном регистре, кроме аббревиатур и официальных обозначений.

## 5. Обертки

Обертка допустима, если она:

- группирует связанные элементы;
- нужна layout-композиции;
- является частью самостоятельного компонента;
- необходима для доступности;
- ограничивает/позиционирует media;
- является обоснованной целью анимации/JS.

Не добавлять слой только «чтобы удобнее покрасить» или потому, что Vue-компоненту якобы нужен один root: Vue 3 поддерживает fragments.

Плохо:

```html
<div class="provider-settings__inner">
  <div class="provider-settings__content">
    <div class="provider-settings__body">...</div>
  </div>
</div>
```

Если группировка не нужна:

```html
<section class="provider-settings">...</section>
```

## 6. Компоненты и контекст

Внутренняя структура компонента не должна зависеть от конкретной страницы. Страница отвечает за размещение, компонент — за собственную структуру и поведение.

Vue-компонент создается, когда есть самостоятельная ответственность, переиспользование или полезная изоляция логики. Не разбивать каждый тег в отдельный `.vue`-файл и не оставлять огромную route page только ради избегания компонентов.

Props передают данные/варианты, emits — события. Компонент не ищет родителя по DOM-классу и не изменяет внешнюю страницу напрямую.

## 7. Vue-списки и условия

- `v-for` всегда получает стабильный предметный `:key` (`id`, version id), а не index, если список может изменяться.
- Не использовать один элемент одновременно с `v-if` и `v-for`; фильтровать computed или оборачивать осознанно.
- `v-if` удаляет элемент/состояние из DOM; `v-show` только скрывает визуально. Выбор учитывает keyboard/focus/live behavior.
- После скрытия/удаления интерактивной области фокус переводится в предсказуемое место.
- SSR markup детерминирован; browser-only значения не должны вызывать hydration mismatch.
- Генерируемые `id` для label/aria стабильны между SSR и hydration.

```vue
<li v-for="revision in revisions" :key="revision.id" class="revision-list__item">
  ...
</li>
```

## 8. Недоверенный контент

- `v-html` запрещен для prompt, document, crawl HTML, user message и model answer.
- По умолчанию выводить интерполяцией `{{ value }}`, которая экранирует HTML.
- Markdown проходит server/client allowlist sanitizer и рендерится только утвержденным компонентом.
- Preview исходной страницы показывается как escaped text или в специально изолированном безопасном viewer, не в DOM панели.
- Citation URL берется из server provenance и проверяется; model-generated href напрямую не доверяется.
- Не вставлять недоверенные значения в inline `style`, raw SVG, `srcdoc`, event attributes или URL без scheme validation.

## 9. Кнопки, ссылки и действия

```html
<a class="button" href="/knowledge">База знаний</a>
<button class="button button--primary" type="submit">Сохранить</button>
<button class="button button--ghost" type="button">Отмена</button>
<button class="icon-button icon-button--compact" type="button" aria-label="Добавить">
  <svg class="ui-icon" aria-hidden="true">...</svg>
</button>
```

- Обычная кнопка или ссылка, визуально оформленная как кнопка, всегда использует базовый класс `button`. Базовый нейтральный вариант не получает лишний модификатор.
- Кнопка только с иконкой всегда использует базовый класс `icon-button`; размер, цвет, фон и рамка задаются абстрактными модификаторами `icon-button--*`.
- Если кнопка содержит иконку и текст, она остаётся `button` и получает `button--with-icon`.
- Визуальные иконки выполняются только контролируемым SVG с классом `ui-icon`. Unicode-символы, emoji и icon-font вместо иконок запрещены.
- Контекстный класс допустим только для размещения или поведения. Он не повторяет padding, border, background, color, размер иконки и другие визуальные свойства базового компонента.
- Согласованные варианты кнопок и иконок добавляются на страницу панели `Компоненты` и используют там те же классы, что рабочий интерфейс.
- У каждого `button` явный `type`.
- Нельзя вкладывать интерактивный элемент в другой интерактивный элемент.
- Disabled button использует `disabled`; если действие временно недоступно, рядом есть понятное объяснение.
- Icon-only button имеет `aria-label`; декоративный SVG внутри — `aria-hidden="true"`.
- Кликабельная строка таблицы не заменяет ссылку/кнопку внутри строки.
- Destructive action отличается текстом/подтверждением, а не только красным цветом.

## 10. Формы

Каждое поле имеет постоянную подпись. Placeholder не заменяет label.

Одиночный выпадающий список реализуется только общим `BaseSelect`: компонент сохраняет `listbox`-семантику, клавиатурное управление и единое визуальное поведение. Нативный `<select>` и локальные dropdown-компоненты на route pages не используются.

```vue
<div class="form-field">
  <span class="form-field__label">Режим обхода</span>
  <BaseSelect
    v-model="crawlMode"
    :options="crawlModeOptions"
    label="Режим обхода"
  />
</div>
```

Публичный prop `label` задаёт trigger доступное имя через `aria-label`. Если внешняя подпись связана через `for`, компоненту передаётся совпадающий `id`. Опции передаются данными; страница не повторяет внутреннюю разметку, SVG и CSS списка.

```vue
<div class="field" :class="{ 'has-error': error }">
  <label class="field__label" for="provider-key">API-ключ</label>
  <input
    id="provider-key"
    v-model="key"
    class="field__control"
    type="password"
    name="providerKey"
    autocomplete="off"
    :aria-invalid="Boolean(error)"
    :aria-describedby="error ? 'provider-key-hint provider-key-error' : 'provider-key-hint'"
  />
  <p id="provider-key-hint" class="field__hint">
    Ключ хранится в зашифрованном виде
  </p>
  <p v-if="error" id="provider-key-error" class="field__error">
    {{ error }}
  </p>
</div>
```

- Связанные поля группируются `fieldset`/`legend`, если это улучшает семантику.
- Ошибка связана с полем через `aria-describedby` и не выражается только цветом.
- Обязательность совпадает в UI, runtime schema и server validation.
- После submit error фокус/summary помогает найти первую ошибку.
- Секрет после успешного сохранения очищается из reactive state/input.
- Значение сохраненного provider key никогда не возвращается в форму; UI показывает отдельную mask.

## 11. Таблицы и списки

Табличные данные (модели, jobs, audit) размечаются `table`:

```html
<table class="data-table">
  <caption class="visually-hidden">
    Задания парсинга
  </caption>
  <thead class="data-table__head">
    <tr class="data-table__row">
      <th class="data-table__cell" scope="col">Источник</th>
      <th class="data-table__cell" scope="col">Статус</th>
    </tr>
  </thead>
  <tbody class="data-table__body">
    ...
  </tbody>
</table>
```

Если mobile presentation меняется на карточки, DOM/semantics пересматриваются осознанно; нельзя ломать чтение таблицы только CSS `display` без accessibility-проверки.

Список сообщений, citations, ошибок и навигации использует `ol/ul`, если элементы образуют список.

## 12. Изображения и SVG

- Контентное изображение: meaningful `alt`, `width`, `height`.
- Декоративное: `alt=""`; `aria-hidden="true"` при необходимости.
- Icon SVG внутри именованной кнопки обычно `aria-hidden="true"`.
- Не копировать произвольный SVG из crawl/model output в DOM.
- Виджет предпочитает встроенные контролируемые icons, чтобы не расширять CSP/requests.
- Изображения товаров из внешнего URL не получают выдуманный alt; использовать подтвержденное название/пустой alt по роли.

## 13. Декор и inline-стили

Статические линии, плашки, фоновые акценты и разделители реализуются CSS/pseudo-elements на существующей структуре.

Отдельный декоративный DOM-элемент допустим только как необходимая цель поведения/анимации или при невозможности корректной CSS-реализации; он скрывается от accessibility tree.

Inline `style` запрещен для обычной стилизации. Допустимое исключение — строго типизированные runtime CSS custom properties/геометрические значения компонента, которые нельзя выразить классом; недоверенные строки не передаются.

## 14. Текст и переносы

- Не переписывать продуктовый текст без задачи.
- Uppercase из дизайна реализуется `text-transform`, а не капсом в HTML.
- `<br>` не используется для визуального переноса заголовка/кнопки/карточки. Перенос контролируется шириной и CSS.
- `<br>` допустим, если перенос — часть содержания: адрес, стихотворная/юридическая строка.
- В статическом HTML для коротких смысловых связок используется `&nbsp;` по правилам Newmark.
- В динамических Vue-строках HTML entity не должна приходить как текст. Использовать Unicode non-breaking space (`\u00A0`) только в утвержденной typography transform или хранить обычный текст и решать перенос CSS, где возможно.
- В `title`, meta/OG и machine-readable data используются обычные пробелы.

## 15. Widget

- `<ai-assist>` — host custom element; host page не получает внутреннюю разметку/классы вне Shadow DOM.
- Launcher — `button`.
- Panel имеет выбранную и протестированную dialog/region семантику, доступное имя, focus entry/return и Escape.
- История — список, сообщения — самостоятельные элементы с понятными author labels для screen reader.
- Streaming не объявляет каждый token; live region обновляется дозированно.
- Hidden panel не оставляет tab-focusable descendants.
- Нельзя блокировать scroll/focus host page без корректного восстановления.

## 16. Не добавлять лишний контент

Как в Newmark, название design frame/слоя/колонки не является видимым текстом. Не добавлять самостоятельно:

- заголовки;
- пояснения и marketing copy;
- buttons/links;
- form fields;
- icons/decor;
- empty-state actions;
- tooltips.

Технически необходимое доступное имя (`aria-label`, visually hidden label) допустимо, если оно точно описывает существующее действие и не меняет продуктовый смысл.

## 17. Чеклист разметки

- [ ] Семантические теги выбраны по роли, а не виду.
- [ ] На route page один `h1`, иерархия заголовков последовательна.
- [ ] Нет `div/span` с click вместо `button/a`.
- [ ] Нет лишних оберток и декоративных DOM-элементов.
- [ ] Повторяемые сущности используют списки/таблицы и стабильные Vue keys.
- [ ] Labels, errors, descriptions и field groups доступны.
- [ ] У buttons задан `type`, icon-only actions именованы.
- [ ] Обычные и icon-only кнопки используют соответственно `button` и `icon-button`, без дублирования визуальных стилей в контекстных классах.
- [ ] Все интерфейсные иконки — контролируемые SVG с классом `ui-icon`, без Unicode-символов и emoji.
- [ ] Все одиночные выпадающие списки используют `BaseSelect`; в route-разметке нет нативного `<select>` и локальных копий dropdown.
- [ ] Изображения имеют корректные alt/width/height.
- [ ] Нет небезопасного `v-html`, raw crawl/model HTML и непроверенных URL.
- [ ] Нет inline styles, кроме утвержденных typed CSS variables.
- [ ] `<br>` не управляет визуальным переносом.
- [ ] Visible text не добавлен из названия design layer.
- [ ] Focus/hidden/loading/error/live states проверены клавиатурой.
- [ ] Разметка SSR/hydration детерминирована.
- [ ] Widget не вмешивается в DOM/стили host page.
