# Вопросы и предложения владельцу проекта

Эти пункты не меняют утвержденное ТЗ автоматически. Они требуют решения до соответствующего этапа.

## До production deployment

- Выбрать целевой hosting/регион и способ хранения production secrets: managed secret manager или инфраструктурный аналог.
- Подтвердить production/admin/widget домены.
- Определить способ отправки reset/invite email или временно ограничить создание пользователей администратором.
- Решить, нужен ли отдельный staging с реальным ограниченным AITUNNEL key с первого спринта.

## До интеграции первого магазина

- Подтвердить точный стартовый URL, разрешенные разделы и право/правила автоматического обхода.
- Подтвердить доступный базовый источник: публичный feed URL либо HTML. Доступ к БД/приватному API в pilot исключен.
- Подтвердить, что найденный парсер конкурента относится к тому же источнику, который нужно индексировать первым, либо предоставить актуальный URL/HTML fixtures.
- Утвердить, какие поля считаются источником истины для цены, наличия, минимальной партии и срока поставки.
- Решить, публикуются ли crawl changes вручную всегда или можно автоматически публиковать только unchanged-safe категории после pilot.
- Решить, нужны ли изображения ассистенту в MVP. Архитектура сейчас хранит metadata/URL, но не копирует и не анализирует изображения.

## До pilot

- Утвердить приветствие, тон ответа, fallback и контактный CTA.
- Выбрать начальную chat/embedding модель по реальному AITUNNEL каталогу, eval, latency и бюджету; не фиксировать название модели только по текущей популярности.
- Определить дневной/месячный бюджет проекта и поведение при его исчерпании.
- Утвердить срок хранения диалогов, необходимость хранения полного текста и пользовательское уведомление/согласие.
- Провести юридическую проверку privacy/152-ФЗ, пользовательского уведомления, обработки данных AITUNNEL и правил парсинга источника.
- Определить support/incident owner и окно реакции на неправильные цены/наличие.

## Возможности после MVP

- Загрузка XML/YML/CSV-выгрузок с preview/diff и ручной публикацией.
- Исследование безопасного DB snapshot import через изолированный ingestion-worker; только после threat model, security review и нового ADR.
- Lead capture/передача в существующую форму или CRM.
- Server-side инструменты для проверки живого наличия/цены и оформления заявки с явным подтверждением.
- File/PDF ingestion с отдельным security pipeline.
- Автоматическое offline quality evaluation и approval gates.
- Отдельный public API service только после измеренной необходимости.
